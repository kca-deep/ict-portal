### 우선순위와 일정 리스크 (15분)

- **AI 챗봇은 6월 말 필수 완성**. 11회차(6/23)에 배포까지 완료 목표.

리스크가 발생할 수 있는 구간:
- 4~6회차 (Supabase + 임베딩 + 검색) - 외부 서비스 연동이 많아 지연 가능

지연이 발생하면 크롤러 시작이 7월로 밀린다. AI 챗봇 완성을 최우선으로 둔다.

## Part 2. PIMS 서비스 구조 + 현재 코드 상태 (40분)

### PIMS가 만드는 3가지 기능 (15분)

(1) **AI 챗봇 (규정법령 어드바이저)**
- 사용자가 ICT기금 운영 관련 질문 입력
- 내부 규정 문서 + 법제처 법령에서 근거 찾아서 답변 생성
- 답변에 출처 명시 + 인용 자동 검증

(2) **크롤러 (공모사업 파이프라인)**
- 6시간마다 자동 실행
- 7개 기관 사이트에서 공고 수집
- AI가 ICT기금 비R&D 공고인지 분류 후 DB 저장

(3) **중복수혜 조회 (PoC)**
- 신청 과제와 기존 과제 유사도 비교
- 중복 위험도 출력 (후순위, 7월 이후)

### 외부 서비스 5개 (10분)

| 서비스 | 역할 | 비용 |
|--------|------|------|
| Supabase | 데이터 저장 (문서, 공고, 로그) | 사용량 기반 |
| Anthropic (Claude) | 답변 생성, 공고 분류 | 토큰당 과금 |
| Cohere | 임베딩 + 리랭킹 | 토큰당 과금 |
| Vercel | 서비스 운영 + Cron | 월정액 |
| 법제처 OpenAPI | 법령 원문 조회 | 무료 |

### 현재 코드에 이미 들어있는 것 (15분)

브라우저에서 `pnpm dev` 실행하고 `http://localhost:3000` 확인.

이미 만들어진 부분:
- `app/page.tsx` - 챗봇 UI (질문 입력창 + 답변 표시 영역)
- `app/layout.tsx` - 공통 레이아웃
- `app/api/` 폴더 - chat, ingest, cron, duplicate-check, health 엔드포인트 폴더만 생성됨 (대부분 비어있음)
- `lib/ai/` - embedding.ts, llm-router.ts, prompts.ts, rerank.ts (구조만 잡힌 상태)
- `lib/db/` - supabase.ts, search.ts (Supabase 연결 코드)
- `supabase/migrations/` - DB 테이블 생성 SQL 파일들 (실행 전)

앞으로 회차별로 채울 부분:
- `app/api/chat/route.ts` - AI 챗봇 백엔드 (7~10회차)
- `app/api/ingest/route.ts` - 문서 색인 (5~6회차)
- `app/api/cron/crawl-announcements/route.ts` - 크롤러 (12회차~)
- `lib/law/` - 법령 도구 (8회차)
- Supabase 실제 DB 연결 (3~4회차)

> 이번 회차는 `/api/chat`에 임시 응답을 넣어서 화면이 일단 동작하게 만든다.

## Part 3. 첫 코딩 작업: `/api/chat` 임시 응답 구현 (100분)

### 작업 목표 (10분)

현재 상태:
- 브라우저에서 질문을 입력하고 "질문하기" 버튼을 누르면 `/api/chat`을 호출한다
- 그런데 `/api/chat/route.ts`가 존재하지 않아 404 오류가 발생한다

이번 작업으로 만들 상태:
- `/api/chat`이 어떤 질문이 들어와도 미리 정해진 임시 답변을 글자 단위 스트리밍으로 반환한다
- 브라우저 화면에 답변이 한 글자씩 나타나는 것을 확인한다

이 작업의 의미:
- 프론트엔드와 백엔드가 연결되는 흐름을 직접 동작하는 형태로 확인
- 7~10회차에 이 임시 답변 자리에 실제 Claude 호출이 들어간다
- 스트리밍 응답 구조를 미리 잡아두기 때문에 나중에 교체가 쉽다

### Claude Code 사용법 (10분)

프로젝트 폴더에서 `claude` 명령으로 시작.

지시할 때 포함해야 할 것:
- **어떤 파일을 만들 것인가** (파일 경로 명시)
- **어떤 입력을 받는가** (요청 형식)
- **어떤 출력을 주는가** (응답 형식)
- **참고할 기존 코드** (있으면 명시)

지시할 때 굳이 포함하지 않아도 되는 것:
- 코드 문법
- 라이브러리 import 방법
- 변수명

### 실습: Claude Code로 작업 진행 (70분)

**1단계 - 현재 상태 확인 (10분)**

```
pnpm dev
```

브라우저에서 `http://localhost:3000` 열기. 질문을 입력하고 버튼 누르면 오류가 나는 것을 직접 확인.

`app/page.tsx`가 `/api/chat`을 어떻게 호출하는지 Claude Code에 질문:
> "app/page.tsx가 /api/chat을 호출하는 부분을 보여주고, 요청 형식과 응답 처리 방식을 설명해줘"

**2단계 - 임시 응답 엔드포인트 생성 지시 (20분)**

Claude Code에 다음 작업 요청:
> "app/api/chat/route.ts 파일을 만들어줘. 다음 조건이야:
> - POST 요청을 받는다
> - 요청 본문은 { query: string } 형식 JSON
> - 응답은 텍스트 스트리밍 (ReadableStream)
> - 응답 내용은 '질문을 잘 받았습니다. 받은 질문: ' + query + '. (7회차에 실제 Claude 응답으로 교체 예정)' 을 한 글자씩 50ms 간격으로 흘려보낸다
> - Next.js 15 App Router Route Handler 형식
> - app/page.tsx 의 응답 처리 방식과 호환되게"

**3단계 - 결과 확인 (20분)**

브라우저 새로고침 후 질문 입력. 답변이 한 글자씩 화면에 나타나는지 확인.

확인할 항목:
- 질문 입력 후 버튼 클릭 -> 답변이 점진적으로 출력되는가
- 입력한 질문 내용이 응답에 포함되는가
- 에러 메시지가 나오지 않는가

**4단계 - 수정 사이클 경험 (20분)**

Claude Code에 수정 요청을 2~3번 던져본다. 예시:

수정 요청 1:
> "글자 출력 간격을 50ms에서 20ms로 바꿔줘"

수정 요청 2:
> "답변 앞부분에 '안녕하세요. ICT기금 어드바이저입니다.' 한 줄을 추가하고, 그 다음에 빈 줄, 그리고 기존 임시 답변이 나오게 해줘"

각 수정 후 브라우저에서 결과 확인. 의도대로 바뀌었는지 검증.

### 마무리 정리 (10분)

이번 회차에서 완성한 것:
- `app/api/chat/route.ts` - 임시 스트리밍 응답 엔드포인트
- 프론트엔드 -> 백엔드 호출 -> 스트리밍 응답 흐름이 한 번 동작

Claude Code 사용 사이클을 1회 이상 경험:
- 무엇을 만들지 지시
- 결과를 브라우저에서 확인
- 수정 요청을 던지고 다시 확인
