*ICT기금 사용자 중심 AX서비스 · 기금사업성과팀 · 2026-07-20 기준*

## 1. 개요

**PIMS**는 ICT기금 사업에 참여하는 **외부 기관 담당자**가 로그인 없이 이용하는 AI 챗봇 서비스이다. 복잡한 기금 규정과 관련 법령을 담당자마다 다르게 해석하던 문제를, AI가 **내부 규정과 법제처 법령을 근거로 인용해** 일관되게 답하도록 해소하는 것이 목표이다. 서비스의 중심은 **① 규정·법령 어드바이저**이며, 공모사업 크롤러(②)·중복수혜 조회(③)가 이를 보조한다.

인증 모델은 **no-login**이다. 회원가입·계정을 두지 않고 사용자 식별은 요청 IP로 하며(감사 로그·레이트리밋 키), 관리자 화면만 별도 인증한다. 공개 엔드포인트가 유료 LLM을 호출하므로 **봇차단·레이트리밋·비용가드가 핵심 방어선**이다.

**개발 현황**: 2026년 5월 20일 착수 이래 **128개 커밋**으로 ① 챗봇 핵심(검색·재정렬·스트리밍 UI)과 관리자 운영 콘솔, no-login 상용 하드닝을 완료하였다. 6월 말 챗봇 개발 완료 → 7월 하드닝 → **7월 말 정식 오픈** 일정 위에 있다.

## 2. 핵심 기능 및 구현 로직

### 2.1 규정·법령 어드바이저 (RAG 챗봇) — 핵심 기능

사용자 질의 한 건은 다음 파이프라인을 통과한다.

1. **진입 가드(4단)** — 과금 전에 ① BotID 봇차단 → ② 레이트리밋 → ③ 비용가드 → ④ 입력 캡(대화 턴·글자 수 상한)을 순차 통과시켜, 무인증 유료 엔드포인트를 봇·과다 호출·예산 초과로부터 보호한다.

2. **병렬 검색** — 내부 규정(임베딩 하이브리드 검색, 최대 30건)과 법제처 법령 조문(의미검색, 최대 50건), 판례, 의도 분해를 **동시에** 발사한다. 대부분의 단일 질의는 대기 없이 진행돼 첫 응답 지연이 늘지 않는다.

3. **통합 리랭킹** — 규정 청크와 법령 조문을 **하나의 풀에 합쳐 Cohere `rerank-v3.5`로 1회 재정렬**한다. 규정과 법령을 같은 잣대의 관련도 점수(0~1)로 경쟁시켜, 기준치(0.33) 이상 상위 근거만 답변에 주입한다.

4. **답변 생성** — 주입된 근거를 바탕으로 **Claude Sonnet 4.6**이 스트리밍으로 답한다. 시스템 프롬프트가 "제공된 자료 밖 조문은 인용 금지"를 강제한다.

이 구조의 핵심 설계 전환은 **규정/법령 이분법 분기의 폐지**(2026-07-13)이다. 과거에는 관련도 점수로 규정 또는 법령 한쪽만 근거로 택했으나, "규정이 법령을 위임·인용해 **둘 다 근거가 필요한 질의**"에서 한쪽을 버리는 한계가 있었다. 이를 단일 풀 통합 리랭킹으로 개편해 규정·법령 혼합 근거를 함께 제공하도록 바꾸었다.

**복합 질의 의도 분해**: 소형 모델(Claude Haiku)이 "검색 목적이 2개 이상 섞인" 복합 질의를 하위 의도로 분해한다. 지배 의도(예: 기금 어휘)가 법령 검색을 독점해 부차 의도의 법령(예: 채무자회생법)이 후보에 못 드는 문제를, **의도 단위 재검색·재정렬**로 회수한다.

**환각 2중 차단**: ① 프롬프트로 자료 밖 인용을 금지하고, ② 답변에 등장한 「법」 제N조를 법제처 공식 원문과 대조하는 **인용 검증**으로 사후 확인한다. 검색이 이미 회수한 조문은 재조회 없이 통과하고, 모델이 기억으로 인용한 조문만 법제처에 실제 조회해 실존 여부를 판정 → 환각 시 답변 하단에 경고 배지를 표시한다.

| 단계 | 사용 기술 | 역할 |
|---|---|---|
| 임베딩 | OpenAI `text-embedding-3-small` (1024차원) | 규정 검색용 질의 벡터화 (색인=쿼리 동일, 영구 고정) |
| 재정렬 | Cohere `rerank-v3.5` | 규정+법령 통합 풀 관련도 채점 (단일 잣대) |
| 답변 LLM | Anthropic `claude-sonnet-4-6` | 근거 기반 답변 스트리밍 |
| 법령 조회 | 법제처 OpenAPI 자체 구현 (`lib/law/`) | 조문 검색 + 인용 검증 + 캐싱 |

### 2.2 관리자 운영 콘솔

`/admin` 화면만 **아이디+비밀번호 + 서명 `__Host-` httpOnly 쿠키**로 보호한다. 자격증명은 상수시간 비교로 검증하고, 로그인 시도는 **브루트포스 리밋**(IP당 10분 10회)으로 억제한다. 비밀번호를 바꾸면 기존 세션이 자동 무효화된다.

운영 콘솔은 모든 질의·응답 로그(`query_log`)를 통계와 개별 대화로 보여준다. 주요 지표는 **사용량 3지표**(총 질의·고유 이용자·이용률), **자동화 가치 지표**(쉬는 날 사용·평일 저녁·심야 사용 — 사람이 없는 시간대의 이용을 계량), **품질 KPI 5종**(응답시간·환각률·인용 검증률·오류율·만족도 👍/👎), **API 사용량 5종**(답변/보조 LLM·임베딩·재정렬·법제처 호출 토큰)이다. 로그는 분기·기간·환각만·질문 검색 등으로 필터·정렬할 수 있으며, 사용자 피드백(👍/👎)이 만족도 KPI로 집계된다.

### 2.3 보안·비용 방어선 (no-login 상용 하드닝)

공개 접근 서비스의 접근·비용 통제를 위해 다층 방어를 구축하였다.

- **레이트리밋 3종**(Upstash Redis) — IP 분당 20회·IP 일일 500회·전역 일일 2,000회. 저장소 장애 시 프로덕션은 **fail-closed**(비용 보호 우선)로 동작한다.
- **비용가드** — 요청 수와 별개로 실제 **토큰 소비**(답변+보조 LLM+임베딩 합산)를 IP·전역 일일 예산으로 통제하고, 예산의 80% 도달 시 **하루 1회 이메일 경고**를 발송한다.
- **봇차단·CSP·보안헤더** — Vercel BotID로 자동화 트래픽을 차단하고, 문서 요청에 nonce 기반 CSP·HSTS·클릭재킹 방지 헤더를 적용한다.
- **부팅 가드** — 프로덕션에서 핵심 API 키가 하나라도 없으면 **부팅을 실패시켜**, 런타임 사고를 배포 시점으로 앞당긴다.
