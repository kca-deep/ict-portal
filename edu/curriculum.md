> 작성일: 2026-05-21 (현행화: 2026-06-09, 6월 2주차 기준. 프로덕션 핵심 선행 개발완료 반영)

> 큰 목표 마일스톤
> - AI 챗봇(규정·법령 어드바이저) 개발완료: **6월 말**

## 2. 학습 모듈 개요

- **M0 기반 환경**: Node.js·pnpm·Claude Code CLI·Supabase CLI 설치, MCP 인증, Next.js 15 App Router 파일 규칙, 환경변수 구성.
- **M1 데이터 계층**: Supabase 클라우드 프로젝트, SQL 마이그레이션(pgvector, documents·regulation 등 테이블), RLS와 service_role 패턴.
- **M2 검색 파이프라인**: 문서 파싱·청킹·OpenAI 임베딩 색인, hybrid_search(BM25+pgvector+RRF), Cohere Rerank 재정렬, 검색 품질 평가.
- **M3 LLM/도구 사용**: Anthropic Claude 스트리밍과 프롬프트 캐싱, Tool Use 루프, 법령 도구와 인용 검증.
- **M4 채팅 UI**: Route Handler 스트리밍, 채팅 화면 컴포넌트, 질의-검색-LLM-화면 end-to-end 연결, 질의 로그 적재.
- **M5 배포/Auth**: Vercel 배포와 환경변수·실행시간 설정, Supabase Auth 로그인(외부 기관 담당자 대상, 초대·승인 기반 계정 발급, 공개 가입 차단), RLS 최종 확인.
- **M8 보안·운영 하드닝**: API 접근 제어(인증·레이트리밋), 색인 API 보호, 에러 메시지 일반화, 입력 길이·턴 수 제한, 외부 호출 타임아웃·재시도, 비용 가드.
- **M9 관리자 채팅 로그**: 모든 질의·응답을 `query_log`에 적재(질의·답변·근거·지연·토큰·분기 결과). 관리자 전용 화면에서 통계(집계)와 개별 대화 세부 내용을 조회.
- **M6 크롤러**: Vercel Cron, fetch+cheerio HTML 파싱, 공고 수집·AI 분류·임베딩 색인, 다중 사이트 확장.
- **M7 중복수혜(선택)**: 사업 이력 임베딩 색인, 코사인 유사도 중복 판별, 민감정보 마스킹과 결과 관리 UI.

## 6. 프로덕션 하드닝 체크리스트 (오픈 전)

현재 프로덕션은 핵심 기능이 동작하지만, 외부 오픈 전에 아래 취약·미흡 항목을 보완한다. 우선순위는 위에서 아래로 높다.

**오픈 전 필수 (Critical)**

- [ ] **색인 API 보호** — `/api/ingest`가 현재 무인증이며 관리자 권한 키로 데이터베이스에 쓴다. 외부 노출 시 임베딩 비용 폭증·데이터 오염이 가능하다. 외부 기관 담당자는 절대 색인할 수 없어야 하므로, 관리자 전용으로 잠그거나 색인을 스크립트 전용으로 두고 이 API를 제거한다.
- [ ] **채팅 API 접근 제어** — `/api/chat`이 현재 무인증·무제한이다. 이용 대상이 인가된 외부 기관 담당자이므로 **로그인 필수 게이트**(Supabase Auth, 초대·승인 기반 계정 발급, 공개 가입 차단)를 적용하고, **기관·사용자별 레이트리밋**과 비용 상한을 둔다.
- [ ] **에러 메시지 일반화** — 현재 내부 오류 메시지(데이터베이스·함수 오류)가 클라이언트로 그대로 전달된다. 사용자에게는 일반 메시지를 주고, 상세는 서버 로그에만 남긴다.
- [ ] **입력 제한** — 질문 길이와 대화 턴 수 상한이 없다. 상한을 둬 비용 남용과 컨텍스트 폭주를 막는다.

**오픈 직후 / 병행 (High)**

- [ ] **외부 호출 타임아웃·재시도** — 임베딩·재정렬·LLM 호출에 타임아웃과 제한적 재시도(백오프)가 없다. 한 곳이 지연·실패하면 요청 전체가 실패한다.
- [ ] **비용 가드** — 일·사용자별 호출 상한과 토큰 정책을 둔다.
- [ ] **관리자 채팅 로그(M9)** — 모든 질의·응답을 `query_log`에 적재한다(질의·답변·근거·지연·토큰·분기 결과). 현재 테이블만 있고 적재되지 않는다.

**품질·유지보수 (Medium)**

- [ ] **SDK 타입 정리** — Anthropic SDK 임시 타입 캐스트를 SDK 업그레이드로 제거한다.
- [ ] **보안 헤더·오리진 점검**, **`/api/health` 확장과 업타임 모니터링**.
- [ ] **최소 테스트·CI** — 검색·분기·에러 경로에 대한 기본 테스트와 자동 빌드 점검.

## 7. 관리자 채팅 로그 (M9) — 통계 + 세부 조회

오픈 운영을 위해 관리자가 챗봇 사용 현황을 보는 화면을 만든다. 두 층으로 구성한다.

**(1) 적재** — 매 질의 처리 시 `query_log`에 비동기로 한 건씩 남긴다.

- 기록 항목: 질의 시각, 질문, 답변, 사용한 근거(내부 규정/법령), 분기 결과(내부 규정 vs 법령)와 관련도 점수, 응답 지연(ms), 토큰 사용량, **사용자 식별자와 소속 기관**(로그인 필수이므로 항상 남는다).

**(2) 관리자 화면** — 관리자 권한 사용자만 접근한다.

- **통계(집계)**: 일·주별 질의 수, **기관별 사용량**, 자주 묻는 질문, 평균 응답 지연, 내부 규정 대 법령 분기 비율, 토큰·비용 추이.
- **세부 조회**: 개별 대화를 열어 질문·답변 전문, 그때 사용한 근거 문서와 관련도 점수, 지연·토큰, **누가(어느 기관) 물었는지**까지 확인. 기간·기관·키워드·분기 종류로 필터.

> 관리자 채팅 로그 바이브코딩 프롬프트
> 챗봇이 답할 때마다 질의·답변·근거·분기 결과·관련도 점수·응답 지연·토큰과 함께 로그인한 사용자와 소속 기관을 `query_log`에 비동기로 적재해 줘. 그리고 관리자만 들어갈 수 있는 화면을 만들어서, 위쪽엔 일·주별 질의 수와 기관별 사용량, 내부 규정 대 법령 분기 비율, 평균 응답 지연 같은 통계를 보여 주고, 아래쪽엔 개별 대화를 눌러 질문·답변 전문과 사용한 근거·관련도 점수·소속 기관까지 보는 세부 조회를 넣어 줘. 기간·기관·키워드·분기 종류로 필터도 가능하게 해 줘.
