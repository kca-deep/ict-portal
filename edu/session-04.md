## 0. 출발점 — 지금 어디까지 와 있나 (가장 먼저 볼 것)

이번 회차는 **새 기능을 처음부터 만드는 게 아니라, 이미 완성된 백엔드를 화면이 따라잡는 회차**다. 그래서 무엇이 끝났고 무엇이 남았는지부터 분명히 한다.

| 구분 | 항목 | 상태 |
|---|---|---|
| **백엔드(서버)** | 1차 검색 30건 → Cohere Rerank 상위 8건 | ✅ 완료 |
| | 관련도 분기(기준치 미만 또는 적합성 게이트 → 법령) | ✅ 완료 |
| | 법령 조회 — **법제처 OpenAPI 직접 호출**(`lib/law/search.ts`) | ✅ 완료 |
| | **약칭 확장**(화관법→화학물질관리법 등, `lib/law/abbreviations.ts`) | ✅ 완료 |
| | **인용 검증**(✓ 실존 / ✗ 없음 / ⚠ 확인불가, `lib/law/verify.ts`) | ✅ 완료 |
| | 스트림 이벤트 송출: `sources` · `routing` · `delta` · **`citations`** · `done` · `error` | ✅ 완료 |
| **프론트(화면)** | 멀티턴 대화·스트리밍·마크다운 렌더 | ✅ 완료 |

| | 법제처 뱃지·관련도 % 표시 | ✅ 부분 완료 |

| | **출처 뱃지 📘 내부규정 / ⚖️ 법령** 체계 | ❌ **미완 — 이번 회차** |
| | **인용 검증 결과·환각 경고** 표시 | ❌ **미완 — 이번 회차** |
| | 답변 복사 · 예시 질문 칩 · 생성 중단 · 맨 아래로 · 진행 상태 | ❌ **미완 — 이번 회차** |

> **가장 중요한 사실**: 서버(`app/api/chat/route.ts`)는 이미 분기 결과(`routing`)와 인용 검증 결과(`citations`)를 **매 답변마다 보내고 있다.** 그런데 화면(`app/page.tsx`)은 이 두 신호를 **받기는커녕 타입에도 정의해 두지 않아 그냥 흘려버린다.** 즉 **공들여 만든 검증 결과가 사용자에게 안 보인다.** 이번 회차 1순위는 이 두 신호를 화면에 드러내는 것이다.

> **MCP 관련 한 줄 정정**: 지난 회차(3회차) 문서는 법령 조회를 "korean-law MCP"로 적었으나, **프로덕션은 MCP 서버를 띄우지 않고 법제처 OpenAPI를 우리 소스코드로 직접 호출**하는 방식으로 구현했다(약칭 확장·인용 검증 포함). korean-law MCP는 **개발·검증 단계의 레퍼런스**로만 썼다. 무상태 서버리스(Vercel)·저지연·라이트셋업(PoC) 원칙에 직접 호출이 맞기 때문이다. 사용자 화면 동작에는 차이가 없다.

## 1. 이번 회차가 다루는 것

| 묶음 | 항목 | 한 줄 |
|---|---|---|
| **A. 숨은 신호 드러내기** | 분기 결과 표시 | "이 답은 내부규정으로 / 법령으로 답했다"를 보여 준다 |
| | 인용 검증 표시 | AI가 댄 "○○법 제N조"가 실제인지 ✓/✗/⚠로 보여 준다 |
| **B. 근거 보는 방식** | 우측 근거 패널 | 아코디언 대신, 누르면 옆에서 원문이 열린다 |
| | 출처 뱃지(📘/⚖️) | 근거가 내부규정인지 법령인지 색으로 구분 |
| **C. 쓰기 편하게** | 답변 복사 | 답을 한 번에 복사 |
| | 예시 질문 칩 | 빈 화면에 "이런 걸 물어보세요" |
| | 생성 중단 | 답변 도중 멈추기 |
| | 맨 아래로 | 긴 답변에서 최신으로 복귀 |
| | 진행 상태 | "내부 규정 찾는 중… / 법령 확인 중…" |
| **D. 뒤에서 정리** | 공용 타입 | 화면·서버가 같은 타입을 쓰게 통합 |

> **우선순위**: A(숨은 신호) → B(근거 패널/뱃지) → C(편의) → D(정리). A는 **작업량이 가장 적은데 체감은 가장 크다**(이미 서버가 보내는 걸 받기만 하면 됨). 그래서 맨 먼저 한다.

## 2. 묶음 A — 서버는 이미 보내는데 화면이 안 쓰는 두 신호

### 2-1. 분기 결과(`routing`) — "어느 근거로 답했는가"

서버는 답변을 보낸 뒤 이런 신호를 함께 보낸다.

```jsonc
{ "type": "routing", "route": "law", "score": 0.12,
  "laws": [{ "name": "개인정보 보호법", "lawId": "011357" }] }
// 또는
{ "type": "routing", "route": "regulation", "score": 0.83 }
```

- `route`: 이 답이 **내부규정(regulation)** 으로 답한 것인지 **법령(law)** 으로 답한 것인지.
- `score`: 내부규정 최상위 관련도(0~1).

화면은 이걸 받아 답변 위/아래에 **"📘 내부규정 근거" 또는 "⚖️ 법령 근거(관련도 12%로 법령 전환)"** 같은 한 줄 표시를 붙이면 된다. 사용자가 **출처 성격을 한눈에** 안다.

### 2-2. 인용 검증(`citations`) — "그 법조문이 진짜인가"

법령으로 답한 경우, 서버는 답변 본문의 법조문 인용을 법제처 DB와 대조한 결과를 보낸다.

```jsonc
{ "type": "citations", "hasHallucination": true, "data": [
  { "raw": "개인정보 보호법 제15조", "lawName": "개인정보 보호법",
    "article": "제15조", "status": "verified" },
  { "raw": "같은 법 제999조의2", "lawName": "개인정보 보호법",
    "article": "제999조의2", "status": "not_found",
    "note": "「개인정보 보호법」에 제999조의2 없음" }
]}
```

- `status`: `verified`(✓ 실존) / `not_found`(✗ 없음=환각 의심) / `ambiguous`(⚠ 확인 불가).
- `hasHallucination`: `not_found`가 하나라도 있으면 `true`.

화면은 이걸 받아 **답변 아래에 검증 줄**을 만든다. `hasHallucination`이 `true`면 **눈에 띄는 경고 배너**("⚠️ 일부 인용을 확인할 수 없습니다 — 원문을 확인하세요")를 띄운다. 법령 챗봇에서 **가장 중요한 안전장치**가 비로소 사용자에게 보인다.

> **왜 1순위인가**: 이 두 신호는 **이미 서버가 보내고 있다.** 화면은 받아서 그리기만 하면 된다. **새 백엔드 작업 0, 체감 가치 최대.**

### ▶ 사용자 프롬프트 — 1장

> 지금 우리 챗봇 서버는 답을 보낼 때 **이 답을 '내부 규정'으로 했는지 '법령'으로 했는지**, 그리고 **답에 나온 법 조항이 진짜 있는 조항인지 공식 원문과 대조한 결과(인용 검증)**를 같이 보내고 있어. 그런데 화면이 이걸 안 받고 그냥 버려서 사용자에게 안 보여. 화면이 이 두 가지를 받아서, 답 위에 **'📘 내부 규정으로 답함' 또는 '⚖️ 법령으로 답함(관련도 N%)'** 을 한 줄로 보여 주고, 답 아래에 **'✓ 확인된 인용 / ✗ 확인 안 된 인용 / ⚠ 확인 불가'** 를 보여 줘. **확인 안 된 인용이 하나라도 있으면(= AI가 지어낸 환각 징후)** 눈에 띄게 **"일부 인용을 확인할 수 없어요 — 원문을 확인하세요"** 라는 경고 띠를 띄워 줘.
>
> 그리고 화면과 서버가 **똑같은 데이터 모양을 각자 따로** 적어 둬서 자꾸 어긋나는데(방금 그 신호를 화면이 흘린 것도 이 때문), 그 모양(메시지·근거·신호 종류)을 **한 파일에 모아** 양쪽이 같이 가져다 쓰게 정리해 줘. 화면 동작은 그대로 두고.

## 3. 묶음 B — 근거 표시: 아코디언 → 우측 근거 패널

지금은 답변 아래에서 근거를 아래로 펼친다(아코디언, `app/page.tsx`의 `Sources`/`SourceItem`). 이걸 **누르면 화면 오른쪽에 원문이 뜨는 '근거 패널'** 로 바꾼다. 내부규정·법령(그리고 8월의 공모공고)을 한 화면에서 다루려면, **답변을 계속 보면서 옆에서 근거를 확인**하는 편이 낫기 때문이다.

### 3-1. 화면 구성 (넓은 화면 / 좁은 화면)

```
[넓은 화면(PC) — 평소]            [넓은 화면(PC) — 근거를 눌렀을 때]
┌────────────────────────┐        ┌───────────────┬──────────────────┐
│  PIMS Chat             │        │  PIMS Chat    │ ⚖️ 법령 [2]        │
│                        │        │               │ 개인정보 보호법    │
│  답변 …근거[1][2]…     │   →    │ 답변 …[1][2]… │ 제15조 ── 원문 ── │
│  ⚖️ 법령 근거 · 관련도12%│       │ ⚖️ 법령 근거   │ ✓ 인용 검증 통과   │
│  ┌ 참조문서 2건 ───┐   │        │ ┌참조 2건──┐  │ 시행일 2025-…     │
│  │ 📘[1]  ⚖️[2]    │   │        │ │📘[1] ⚖️[2]│  │ [법제처 원문 ↗]   │
│  └─────────────────┘   │        │ └──────────┘  │                  │
│  [메시지 입력       ▸] │        │ [입력      ▸] │ (오른쪽 패널)     │
└────────────────────────┘        └───────────────┴──────────────────┘
   패널 닫힘 = 채팅 전체폭            근거 클릭 = 오른쪽에 원문 패널

[좁은 화면(휴대폰) — 근거를 눌렀을 때]
┌──────────────┐
│  PIMS Chat   │   근거를 누르면 화면을 가르지 않고
│  답변 …[2]…  │   아래에서 '바텀시트'가 올라와 원문을 덮어 보여 줌
│ ┌─참조 2건─┐ │   (아래로 쓸어내리거나 X로 닫음)
│ ╞══════════╡ │
│ │⚖️ 법령    │ │  ← 아래에서 올라온 시트
│ │제15조 …   │ │
│ └──────────┘ │
└──────────────┘
```

- **넓은 화면**: 오른쪽에 패널이 갈라져 뜬다. 답변과 원문을 나란히 본다.
- **좁은 화면**: 화면을 가르지 않고 **아래에서 시트가 올라와** 원문을 덮는다.
- 공통: **한 번에 하나의 근거**만 열고, 본문의 근거 번호 `[1] [2]`를 누르면 패널이 그 근거로 이동한다.

### 3-2. 근거 종류에 따라 패널 내용이 다르다 (출처 혼동 방지)

근거가 **내부규정인지·법령인지**를 색과 내용으로 분명히 구분한다. 통합 챗봇의 핵심 안전장치다.

| 근거 종류 | 뱃지 | 패널에 보여 줄 것 |
|---|---|---|
| **📘 내부규정** | 파랑 | 조문 본문 + 내부문서번호(예: ICT-OP-2024-008) + 관련도 % |
| **⚖️ 법령** | 보라 | 조문 원문 + **인용 검증 결과(✓/✗/⚠)** + 시행일·법령ID + 법제처(law.go.kr) 원문 링크 |
| **📋 공모공고**(8월 추가) | 초록 | 접수 D-n / 마감됨 + 기관 요약 + 공고 링크 |

> 이번 회차는 **📘 내부규정 · ⚖️ 법령** 2종만 만든다. 📋 공모공고는 8월 크롤러가 붙을 때 **같은 패널에 카드 한 종류만 추가**하면 되도록 구조를 맞춰 둔다.

> **현재 코드와의 차이**: 지금은 법령 근거를 "법제처 법령"이라는 회색 글씨 뱃지로만 구분한다(`SourceItem`의 `isLaw`). 이걸 **📘/⚖️ 색 뱃지 체계**로 정리하고, 법령 카드에는 **2-2의 `citations` 결과**를 연결해 ✓/✗/⚠를 함께 띄운다.

## 4. 묶음 B 보강 — 인용 검증을 근거 패널에 연결

답변 아래 검증 줄(2-2)과 별개로, **법령 근거 카드 안에도** 그 조문의 검증 상태를 표시한다.

- 패널에서 `⚖️ 법령` 카드를 열면, 그 법령의 조문 옆에 **✓ 검증됨 / ✗ 확인 안 됨 / ⚠ 확인 불가** 배지.
- 답변 본문에 `⚠️ 일부 인용 미확인` 경고가 있으면, 해당 근거 카드도 같은 색(주의)으로 강조.

> 핵심: **검증 결과를 "답변 아래 한 줄"과 "근거 카드 안" 두 곳에서** 보이게 한다. 사용자가 답을 읽다가도, 근거를 펼쳐 보다가도 신뢰도를 즉시 가늠한다.

### ▶ 사용자 프롬프트 — 2장

> 답 아래의 참조 문서를 누르면, 지금처럼 아래로 펼치지 말고 **답은 그대로 둔 채 화면 오른쪽에 그 원문이 뜨는 패널**로 바꿔 줘. 답 본문에 있는 **근거 번호 [1] [2]를 누르면** 그 번호의 원문으로 패널이 이동하고, **한 번에 하나만** 열리며, X나 바깥을 누르면 닫히게 해 줘. **넓은 화면에선 오른쪽에 패널이 갈라져** 나란히 보이고, **좁은 화면(휴대폰)에선 아래에서 시트가 올라와** 원문을 덮게 해 줘.
>
> 근거가 무엇이냐에 따라 패널 내용을 다르게 보여 줘. **내부 규정**이면 조문 본문과 내부 문서번호를(파란 📘 뱃지), **법령**이면 조문 원문과 함께 **그 조항이 진짜 있는지 확인한 표시(✓ 확인됨 / ✗ 확인 안 됨)·시행일·법제처(law.go.kr) 원문 링크**를(보라 ⚖️ 뱃지) 보여 줘서 한눈에 구분되게 해 줘. (나중에 8월에 공모공고가 붙으면 **같은 패널에 초록색 '공고 카드' 한 종류만** 더 넣을 수 있게 구조를 맞춰 둬.)

## 5. 묶음 C — 생성 제어·편의 다섯 가지

비전문가(외부 기관 담당자)가 쓰는 화면이라, 작은 매끄러움이 신뢰로 이어진다.

| 기능 | 무엇을 | 왜 | 현재 |
|---|---|---|---|
| **답변 복사** | 답변마다 '복사' 버튼 | 실무에서 바로 붙여 사용 | 없음 |
| **예시 질문 칩** | 빈 화면에 "이런 걸 물어보세요" 버튼 | 처음 쓰는 사람이 막막하지 않음 | 빈 화면 문구만 있음 |
| **생성 중단** | 생성 중 '전송'이 '중단'으로 바뀌고 누르면 즉시 멈춤 | 길거나 엉뚱할 때 바로 끊고 재질문, 비용 절감 | 없음(중단 불가) |
| **맨 아래로** | 위로 올려 읽다 새 글이 이어지면 '↓ 최신으로' 버튼 | 긴 답변·법령 원문에서 길 잃지 않음 | 스크롤 추적만 있고 버튼 없음 |
| **진행 상태** | "내부 규정 찾는 중… / 법령 확인 중…" 한 줄 | 빈 화면 대기 체감 단축, 분기 방향이 드러남 | 없음(점 3개만) |

### 5-1. 생성 중단은 어떻게 — `AbortController`

지금은 답을 만드는 도중에 그 과정을 멈출 방법이 없다. 그래서 **진행 중인 답 생성을 도중에 멈추는 기능**을 붙이고, '중단' 버튼이 그걸 호출하게 한다. 서버는 Node 런타임이라 사용자가 끊으면 답 생성도 함께 멈춘다.

### ▶ 사용자 프롬프트 — 3장

> 챗봇 화면에 네 가지 편의를 더해 줘. ① **답마다 '복사' 버튼**으로 한 번에 복사, ② 대화가 비어 있을 때 **'이런 걸 물어보세요' 같은 예시 질문 버튼** 몇 개, ③ 답이 만들어지는 동안 **'전송' 버튼이 '중단'으로 바뀌고 누르면 바로 멈추기**(멈춘 뒤 곧장 다음 질문 가능), ④ 위로 올려 읽다가 새 답이 이어지면 **'↓ 최신 답변으로' 버튼**이 떠서 한 번에 맨 아래로(맨 아래에 있을 땐 안 보이게). 지금 잘 되는 대화·답변·스크롤은 **그대로 두고** 이 네 가지만 더해 줘.

### 5-2. 진행 상태는 서버 신호가 필요 (작은 백엔드 추가)

"지금 법령 확인 중"이라고 화면이 말하려면, **서버가 단계 신호를 함께 보내야** 한다. 그래서 진행 상태만큼은 **신규 백엔드 이벤트**가 필요하다.

```jsonc
{ "type": "stage", "stage": "searching" }   // 내부 규정 찾는 중
{ "type": "stage", "stage": "reranking" }   // 재정렬 중
{ "type": "stage", "stage": "law_lookup" }  // 법령 확인 중
```

답을 만드는 흐름(검색 → 재정렬 → (분기 시) 법령 조회) 사이에 지금 어느 단계인지 알리는 신호를 끼워 넣고, 화면은 답이 시작되기 전 그 신호를 한 줄로 보여 준다. 다른 편의(복사·예시칩·중단·맨아래로)는 **화면만으로** 끝난다.

### ▶ 사용자 프롬프트 — 4장

> 답이 나오기 시작하기 전에 **지금 무엇을 하는 중인지** 한 줄로 보여 줘. 규정을 찾는 동안엔 "내부 규정 찾는 중…", 관련도를 따지는 동안엔 "관련도 분석 중…", 법을 확인하는 동안엔 "법령 확인 중…"처럼. 이건 답을 만드는 **서버가 지금 어느 단계인지 같이 알려 줘야** 화면에 표시할 수 있으니, 그 신호도 같이 만들어 줘.

## 6. 묶음 D — 뒤에서 한 번 정리: 공용 타입(`lib/types.ts`)

화면에는 안 보이지만 같이 해 두면 좋은 정리다.

- **지금 상태**: `SourceChunk`·`Message`·`StreamEvent` 같은 '데이터 모양'을 **`app/page.tsx`(화면)와 `app/api/chat/route.ts`(서버)가 각자 따로** 적어 둔다. 같은 양식을 두 군데 베껴 쓰는 셈이다.
- **무엇이 문제냐**: 이번에 `routing`·`citations`·`stage` 이벤트와 출처 뱃지를 더하면 **양쪽을 동시에 고쳐야** 하는데, 한쪽을 빠뜨리면 화면이 신호를 흘려버린다(지금 `citations`가 딱 그 상태).
- **무엇을 하나**: 이 타입들을 **`lib/types.ts` 한 곳에 모으고 화면·서버가 함께 import** 하게 한다.

> 비유: 같은 신청서 양식을 부서마다 복사해 쓰면 언젠가 칸이 어긋난다. **원본을 한 곳에 두고 모두 참조**하게 만드는 정리다.

## 7. 구현계획 (단계별)

작은 것부터, 위험이 낮은 순서로 쌓는다. **각 단계가 끝날 때마다 `pnpm build`로 확인**한다.

| 단계 | 작업 | 손대는 파일 | 신규 백엔드 | 체감 |
|---|---|---|---|---|
| **1. 공용 타입 + 숨은 신호** | `lib/types.ts` 신설(Message·SourceChunk·StreamEvent에 `routing`·`citations` 포함) → 화면이 두 이벤트를 받아 **분기 줄 + 인용 검증 줄/경고 배너** 표시 | `lib/types.ts`(신규), `app/page.tsx`, `app/api/chat/route.ts`(타입 import) | 없음 | ★★★ |
| **2. 근거 패널 + 출처 뱃지** | 아코디언 → 우측 패널/모바일 바텀시트. 📘/⚖️ 색 뱃지, 법령 카드에 검증 배지·법제처 링크 연결 | `components/ui/source-panel.tsx`(신규), `app/page.tsx` | 없음 | ★★★ |
| **3. 편의 4종** | 답변 복사, 예시 질문 칩, 생성 중단(AbortController), 맨 아래로 버튼 | `app/page.tsx`, `components/ui/response.tsx` | 없음 | ★★ |
| **4. 진행 상태** | 서버에 `stage` 이벤트 추가 → 화면이 "찾는 중/법령 확인 중" 한 줄 표시 | `app/api/chat/route.ts`, `lib/types.ts`, `app/page.tsx` | **`stage` 이벤트** | ★★ |

> **순서가 핵심**: 1단계가 가장 싸고 가장 값지다(서버가 이미 보내는 신호 받기). 1단계에서 공용 타입을 먼저 세워 두면 2~4단계에서 화면·서버가 어긋날 일이 없다.

## 9. 핵심 용어 (한 줄 정의)

| 용어 | 한 줄 설명 |
|---|---|
| **스트림 이벤트** | 답을 한 번에 주지 않고, 조각(답글자·근거·분기·검증)을 순서대로 흘려보내는 신호. 화면은 종류별로 받아 그린다. |
| **`routing`(분기 결과)** | 이 답이 내부규정으로 답한 것인지 법령으로 답한 것인지와 관련도 점수를 담은 신호. |
| **`citations`(인용 검증)** | AI가 댄 법조문이 실제 존재하는지 ✓/✗/⚠로 판정한 결과. 환각 여부(`hasHallucination`) 포함. |
| **인용 검증 / 환각** | AI가 댄 "○○법 제N조"를 공식 원문과 대조해 맞는 것만 남기는 것 / AI가 없는 내용을 사실처럼 지어내는 현상. |
| **약칭 확장** | "화관법" 같은 줄임말을 "화학물질관리법" 정식 명칭으로 펴서 검색 적중률을 높이는 것. |
| **근거 패널 / 바텀시트** | 답변 옆(넓은 화면) 또는 아래(좁은 화면)에서 근거 원문을 보여 주는 영역. |
| **출처 뱃지** | 근거가 내부규정(📘)인지 법령(⚖️)인지 색으로 구분하는 표시. |
| **`AbortController`** | 진행 중인 네트워크 요청을 도중에 취소하는 표준 수단. '생성 중단'에 쓴다. |
| **공용 타입** | 화면과 서버가 함께 쓰는 '데이터 모양' 정의를 한 파일에 모아 둔 것. 중복·어긋남 방지. |

## 10. 직접 만져보며 복습하기 (회차 후)

1. **내부규정에 있는 질문**을 던져, 답변 위에 **'📘 내부규정 근거'** 가 뜨는지 확인한다.
2. **내부규정에 없는 법령 질문**을 던져, **'⚖️ 법령 근거(관련도 N%)'** 로 전환되고 법령 원문이 근거로 붙는지 확인한다.
3. 일부러 **존재하지 않는 법조문**으로 답이 유도되는 질문을 던져, 답변 아래 **'✗ 확인 안 됨' + 경고 배너**가 뜨는지 확인한다(인용 검증).
4. 근거를 눌러 **우측 패널(모바일은 바텀시트)** 이 열리고, 본문 `[1][2]`를 누르면 해당 근거로 이동하는지 확인한다.
5. **📘 내부규정 / ⚖️ 법령** 뱃지 색이 구분되고, 법령 카드에 검증 배지·법제처 링크가 있는지 확인한다.
6. **답변 복사·예시 질문 칩**이 동작하고, **'중단'** 버튼으로 답변을 도중에 멈출 수 있는지, 긴 답변에서 **'↓ 최신으로'** 가 뜨는지, 답 시작 전 **진행 상태**("법령 확인 중…")가 보이는지 확인한다.
