# 3회차 - 검색 정밀도 높이기(Rerank 연결) + 챗봇 화면 개선 + 법령 실시간 조회(korean-law MCP)

> 이 문서는 회차 진행 전 **초안**이다. 화면 개선 항목과 일정은 진행하며 확정한다.

| 항목 | 내용 |
|------|------|
| 날짜 | 미정 (예정) |
| 이번 주제 | ① 검색 결과 재정렬(Rerank) 연결 · ② 챗봇 화면(UI) 개선 · ③ 법령 실시간 조회(korean-law MCP) |

> **이번 회차 한 줄 요약**
> 답변의 품질을 높이는 회차다. 검색으로 찾은 후보를 더 정밀하게 추려 근거의 정확도를 올리고(①), 챗봇 화면을 더 쓰기 편하게 다듬고(②), 내부 규정으로 답할 수 있으면 내부 규정을 근거로 답하고 내부 규정에 없으면 외부 법령을 실시간으로 조회해 답하도록 한다(③).

## 1. 이번 회차가 다루는 3가지

| 주제 | 무엇을 하나 |
|---|---|
| **① Rerank 연결** | 1차 검색으로 넓게 찾은 후보를, 질문과 더 잘 맞는 것만 정밀하게 추려 남긴다. |
| **② 화면(UI) 개선** | 이미 동작하는 대화 화면에, 실무에서 자주 필요한 기능을 더한다. |
| **③ korean-law MCP** | 내부 규정 검색의 관련도가 낮을 때(내부 규정에 마땅한 근거가 없을 때) 대한민국 법령·판례를 공식 출처에서 실시간 조회해 답한다. |

세 가지는 따로 노는 작업이 아니라 **"더 정확한 답"** 이라는 한 가지 목표로 모인다.

> 용어 한 줄 정리
> **RAG**: 우리 데이터베이스에 넣어 둔 문서를 검색해, 그 내용을 근거로 AI가 답하게 하는 방식.
> **임베딩**: 문장을 의미가 담긴 숫자 목록(벡터)으로 바꾼 것. 비슷한 의미일수록 숫자가 가까워, 의미 기반 검색에 쓴다.
> **벡터**: 임베딩이 만들어 낸 숫자 목록. 이 숫자끼리의 거리로 의미가 가까운지 판단한다.

## 2. 주제 ① — 검색 결과 재정렬(Rerank) 연결

### 먼저, 흔한 오해부터 바로잡는다 (가장 중요)

- ❌ **오해**: "검색을 더 잘하려면 임베딩을 OpenAI에서 Cohere로 바꾸고 문서를 다시 색인해야 한다."
- ✅ **사실**: 임베딩은 **OpenAI `text-embedding-3-small`(1024차원)을 그대로 둔다. 바꾸지 않고, 다시 색인하지도 않는다.**

왜 그런가. **임베딩(1차 검색)** 과 **Rerank(재정렬)** 는 서로 **다른 단계**이기 때문이다.

- 임베딩은 문서를 숫자 목록(벡터)으로 바꿔 그 숫자끼리의 거리로 비교한다. 이때 문서를 넣을 때 쓴 도구와 질문을 변환할 때 쓰는 도구가 **같아야** 숫자를 맞대 볼 수 있다. 그래서 임베딩은 OpenAI로 통일해 둔다.
- **Rerank는 벡터(숫자)를 보지 않는다.** **질문 원문(텍스트)과 후보 문서 원문(텍스트)** 을 직접 맞대 보고 점수를 매긴다. 채점 방식이 임베딩과 무관하므로, 임베딩이 OpenAI여도 Rerank는 Cohere로 자유롭게 조합할 수 있다.
- 결론: Rerank는 기존 검색 위에 **거름망 한 단계를 추가**하는 것이지, 기존 검색을 교체하거나 문서를 다시 색인하는 것이 **아니다.**

### 무엇을 하나

1. **1차 검색은 지금 그대로** — OpenAI 임베딩으로 후보를 **넓게 약 30건** 찾는다.
2. **재정렬 단계를 추가** — 그 30건을 **Cohere Rerank** 가 질문과 1:1로 비교해 **상위 약 8건**만 남긴다.
3. AI는 이제 **정밀하게 추려진 약 8건**만 받아 답한다.

> 용어 한 줄 정리
> **Rerank(재정렬)**: 1차 검색으로 모은 후보를, 질문과 각 후보의 **원문 텍스트**를 1:1로 비교해 적합한 순서로 다시 줄 세우는 단계.

### 현재 완성도

- Cohere Rerank를 호출하는 코드(`lib/ai/rerank.ts`)는 **이미 작성되어 있다.**
- 다만 챗 흐름에는 **아직 연결되어 있지 않아**, 지금은 1차 검색 상위 8건을 그대로 사용한다.
- **이번 회차의 핵심 작업 = 이 Rerank 단계를 챗 라우트(`app/api/chat`)에 실제로 연결하는 것이다.**

### 왜 하나

규정과 법령은 **정확히 들어맞는 한 조항**이 중요한 분야다. 의미가 대충 비슷한 자료보다 질문에 **정확히 맞는 자료**를 골라 근거로 쓰면 답의 신뢰도가 크게 올라간다. 그래서 후보를 한 번 더 정밀하게 거르는 재정렬의 효과가 크다.

### 끝나면 이렇게 달라진다

- 답변에 **엉뚱한 규정이 섞일 확률**이 줄어든다.
- 답변 아래 "참조 문서"가 **실제 근거에 가까운 것**들로 채워진다.

### 한 가지 더 — Rerank 점수는 "분기 신호"로도 쓴다

Rerank는 각 후보에 **관련도 점수(0~1 사이의 값. % 로 보면 된다)** 를 매긴다. 이 점수는 후보를 줄 세우는 데만 쓰는 게 아니라, **"내부 규정이 이 질문을 제대로 다루고 있는가"** 를 판단하는 신호로도 쓸 수 있다. 상위 결과의 관련도가 높으면 내부 규정에 답이 있다는 뜻이고, 낮으면 내부 규정에 마땅한 근거가 없다는 뜻이다. 이 점수를 ③(법령 조회)의 분기 기준으로 재활용한다(4절에서 설명).

### 바이브코딩 프롬프트

> 검색 흐름에서 **임베딩은 OpenAI `text-embedding-3-small`(1024차원) 그대로 두고**, 절대 교체하거나 재색인하지 마. 1차 검색으로 후보를 약 30건 찾은 뒤, **`lib/ai/rerank.ts`의 Cohere Rerank로 상위 약 8건만** 남기도록 챗 라우트(`app/api/chat`)에 연결해 줘.

> Rerank를 적용하기 **전과 후**에, 같은 질문으로 참조 문서가 어떻게 달라지는지 비교해서 보여 줘.

## 3. 주제 ② — 챗봇 화면(UI) 개선

대화·답변 표시·근거 표시·스크롤은 이미 동작한다. 이제 **실무에서 쓰다 보면 아쉬운 부분**을 채운다. 아래는 후보다. 이번 회차에 무엇을 넣을지 고른다. 전부 할 필요는 없다.

| 후보 | 무엇 | 효과 | 추천도 |
|---|---|---|---|
| **답변 복사 버튼** | AI 답변을 한 번에 복사 | 실무에서 바로 붙여 사용 | 높음 |
| **예시 질문 칩** | 빈 화면에 "이런 걸 물어보세요" 버튼 제시 | 처음 쓰는 사람이 막막하지 않음 | 높음 |
| **근거 → 원문 점프** | 참조 문서를 누르면 해당 규정·법령 원문으로 이동 | 신뢰와 검증 강화 | 높음 |
| **출처 뱃지(내부규정/법령)** | 근거가 내부 규정인지 외부 법령인지 표시 | 출처 신뢰도, ③번과 연계 | 높음 |
| **대화 저장·이어보기** | 새로고침해도 대화가 유지됨 | 끊김 없는 사용 | 중간 |
| **답변 다시 생성** | 같은 질문을 다시 요청 | 답이 마음에 들지 않을 때 | 중간 |
| **모바일 화면 정리** | 좁은 화면에 맞게 정리 | 외부·현장 사용 대비 | 중간 |

> **권장 조합**: "답변 복사 + 예시 질문 칩 + 근거 원문 점프 + 출처 뱃지" 4가지. 작업량 대비 체감이 크고, 출처 뱃지는 ③(법령 MCP)과 자연스럽게 이어진다.

### 바이브코딩 프롬프트

> 챗봇 화면에 다음 4가지를 추가해 줘. ① 답변마다 복사 버튼, ② 대화가 비어 있을 때 예시 질문 칩 몇 개, ③ 참조 문서를 누르면 해당 규정·법령 원문으로 이동, ④ 각 근거에 "내부규정" 또는 "법령" 출처 뱃지 표시. 기존 대화·답변 표시 동작은 그대로 유지해 줘.

## 4. 주제 ③ — 법령 실시간 조회(korean-law MCP)

### MCP가 무엇인가

> 용어 한 줄 정리
> **MCP(Model Context Protocol)**: AI(Claude)가 외부 도구·자료에 직접 접속하도록 정해 둔 표준 연결 방식.
> **korean-law MCP**: 그 연결이 **법제처(law.go.kr)**, 즉 대한민국 법령·판례의 공식 출처에 닿아 있는 MCP. 이를 통해 법령을 실시간으로 조회한다.

### korean-law MCP가 할 수 있는 일

| 할 수 있는 것 | 쉽게 말하면 |
|---|---|
| 법령 검색 | "전자금융거래법" 같은 법을 찾기 |
| 법령 조문 원문 가져오기 | 특정 조문의 **정확한 원문 텍스트** 받기 |
| 판례 검색·원문 | 관련 판례를 찾고 내용 보기 |
| 별표·서식 | 법에 딸린 표·서식 받기 |
| **인용 검증** | AI가 "○○법 제○조"라고 했을 때, 그것이 실제와 맞는지 **공식 원문과 대조** |
| 개정 추적 | 그 조항이 언제 어떻게 바뀌었는지 확인 |

### 내부 규정(RAG) vs 법령(MCP)

| | 내부 규정 (우리 데이터베이스·RAG) | 법령·판례 (korean-law MCP) |
|---|---|---|
| 어디 있나 | 우리가 직접 넣은 문서 | 법제처 공식 서버 |
| 최신성 | 우리가 직접 갱신해야 함 | 실시간 조회라 항상 최신 |
| 정확성 | 조각 단위로 저장해 일부 누락 가능 | 공식 원문 그대로 |
| 적합한 용도 | 우리 기관 내부 규정·지침 | 자주 바뀌는 외부 법령·판례 |

핵심: 근거는 **내부 규정(우리 데이터베이스·RAG)** 과 **법령·판례(법제처·MCP)** 두 갈래가 있고, 질문마다 관련도에 따라 **둘 중 하나를 골라** 답한다(분기 방식은 바로 아래에서 설명). 법령은 자주 바뀌고 정확한 원문이 중요하므로, 우리가 복사해 두기보다 그때그때 공식 출처에서 실시간으로 받아오는 것이 안전하다.

### 언제 내부 규정으로, 언제 법령으로? — 관련도 기준 분기

이번 회차의 핵심 설계다. 내부 규정과 법령을 **항상 동시에 합쳐 쓰지 않는다.** 대신 **내부 규정 검색의 관련도 점수를 기준으로 둘 중 하나로 분기**한다. 먼저 용어부터 정리한다.

> 용어 한 줄 정리
> **관련도 점수**: Rerank가 상위 후보에 매긴 0~1 사이의 점수(% 로 보면 된다). 질문과 그 문서가 얼마나 잘 맞는지를 나타낸다.
> **기준치(threshold)**: 분기를 가르는 경계값. 이 값 이상이면 "내부 규정에 있다", 미만이면 "내부 규정에 없다"로 본다.
> **분기(라우팅)**: 조건에 따라 처리 경로를 둘 중 하나로 가르는 것.

처리 규칙은 다음과 같다.

1. 질문이 들어오면 **먼저 내부 규정을 1차 검색 → Rerank** 한다(2절의 ①). 이때 상위 결과의 **관련도 점수**가 나온다.
2. **관련도가 기준치 이상이면** = 내부 규정이 이 질문을 다루고 있다고 본다 → **내부 규정만 근거로** AI가 추론해 답한다. (법령 조회는 하지 않는다.)
3. **관련도가 기준치 미만이면** = 내부 규정에 마땅한 근거가 없다고 본다 → **korean-law MCP로 법령·판례를 실시간 조회**해, 그것을 근거로 답한다.

| 관련도 점수 | 판단 | 근거로 쓰는 것 |
|---|---|---|
| 기준치 **이상** | 내부 규정에 있음 | 내부 규정(RAG) 결과만 |
| 기준치 **미만** | 내부 규정에 없음 | korean-law MCP로 받은 법령·판례 |

기준치를 얼마로 둘지는 실제 질문으로 맞춰 가며 정한다(예: 0.4 = 40% 같은 식). 너무 높이면 내부 규정에 있는데도 법령을 부르고, 너무 낮추면 내부 규정에 없는데도 억지로 내부 규정으로 답하려 한다.

법령으로 분기된 경우, MCP로 받은 조문은 **인용 검증**을 거쳐 실제와 맞는지 확인한 뒤 답의 근거로 쓴다. 답에는 그 근거가 내부 규정인지 법령인지 출처를 함께 표시한다.

### 인용 검증으로 환각 막기

> 용어 한 줄 정리
> **환각**: AI가 실제로는 없는 내용을 사실처럼 그럴듯하게 지어내는 현상.
> **인용 검증**: AI가 댄 "○○법 제○조"를 공식 원문과 대조해, 실제로 존재하고 맞는 인용만 근거로 남기는 것.

법령 챗봇에서 가장 큰 위험은 AI가 **있지도 않은 조항**을 그럴듯하게 지어내는 것이다. korean-law MCP의 인용 검증으로 AI가 댄 법조문을 공식 원문과 대조하면, 사실인 것만 근거로 남기고 지어낸 것은 거를 수 있다.

### 바이브코딩 프롬프트

> 챗 흐름을 이렇게 분기해 줘. 질문이 오면 먼저 내부 규정을 검색하고 Cohere Rerank로 재정렬해. 상위 결과의 관련도 점수가 기준치(우선 0.4로 두고 나중에 조정) 이상이면 내부 규정만 근거로 답하고, 기준치 미만이면 korean-law MCP로 법령·판례를 조회해서 그걸 근거로 답하게 해 줘. 기준치는 환경변수로 빼서 쉽게 바꿀 수 있게 해 줘.

> 법령으로 분기됐을 때 AI가 인용한 법조문은 **인용 검증**을 거쳐 공식 원문과 맞는 것만 근거에 표시하고, 검증되지 않은 인용은 "확인되지 않음"으로 처리해 줘.

> 기준치를 0.3, 0.4, 0.5로 바꿔 가며 같은 질문 모음을 돌려서, 내부 규정으로 답한 것과 법령으로 분기된 것이 의도대로 갈리는지 비교해 줘.

## 5. 셋을 합친 전체 처리 흐름

1. 사용자가 질문을 입력한다.
2. 내부 규정을 1차 검색해 후보를 약 30건 찾는다. (OpenAI 임베딩, 그대로)
3. 그 30건을 Cohere Rerank로 재정렬해 상위 약 8건만 남기고, 상위 결과의 **관련도 점수**를 확인한다. (①)
4. **관련도 점수로 분기한다.** (③)
   - 기준치 **이상** → 내부 규정에 답이 있다고 보고, **내부 규정 근거만**으로 답한다. (법령 조회 안 함)
   - 기준치 **미만** → 내부 규정에 없다고 보고, **korean-law MCP로 법령·판례를 조회**하고 인용 검증을 거쳐 그것을 근거로 쓴다.
5. AI(Claude)가 선택된 근거(내부 규정 또는 검증된 법령)로 답을 작성하고, 실시간으로 한 글자씩 이어 보여 준다(스트리밍).
6. 개선된 화면에 표시한다. 답변 복사, 예시 질문 칩, 근거 원문 점프, 출처 뱃지(내부규정/법령). (②)

요약하면, 더 정확하게 찾고(①), 관련도에 따라 내부 규정과 법령 중 맞는 근거로 답하고(③), 더 쓰기 좋게 보여 준다(②).

## 6. 진행 전 결정할 것 (체크리스트)

- [ ] **Rerank 적용 범위** — `regulation_search`에만 적용할지, `documents` 검색에도 적용할지. (어느 쪽이든 임베딩은 OpenAI 그대로 두며, **재색인은 불필요**하다.)
- [ ] **UI 개선 범위** — 3절의 후보 중 이번 회차에 넣을 항목을 확정한다(권장 4가지 기준).
- [ ] **분기 기준치(threshold)** — 내부 규정으로 답할지, 법령(MCP)으로 넘길지 가르는 관련도 점수 경계값을 정한다. 우선값을 두고 실제 질문으로 조정한다.
- [ ] **점수 기준** — 분기에 쓰는 점수를 Rerank 상위 1건의 관련도로 볼지, 상위 몇 건의 평균으로 볼지 정한다.
- [ ] **출처 표시 규칙** — 답변에서 "내부 규정"과 "법령"을 어떻게 구분해 보여 줄지 정한다.

## 7. 핵심 용어 (한 줄 정의)

| 용어 | 한 줄 설명 |
|---|---|
| **Rerank(재정렬)** | 후보를 질문과 1:1로 비교해 다시 줄 세우는 단계. **벡터가 아닌 원문 텍스트**로 채점하므로 임베딩과 독립이다. |
| **1차 검색 vs Rerank** | 1차 검색은 OpenAI 임베딩으로 넓게(약 30건) 찾는 단계, Rerank는 Cohere로 정밀하게(약 8건) 추리는 단계. 서로 다른 단계라 임베딩 교체·재색인이 필요 없다. |
| **관련도 점수** | Rerank가 후보에 매기는 0~1 사이 점수(% 로 봐도 된다). 질문과 문서가 얼마나 맞는지를 나타낸다. |
| **기준치(threshold)** | 내부 규정으로 답할지 법령으로 넘길지 가르는 관련도 경계값. |
| **분기(라우팅)** | 관련도 점수에 따라 처리 경로를 내부 규정 또는 법령(MCP) 중 하나로 가르는 것. |
| **MCP** | AI가 외부 도구·자료에 직접 접속하도록 정해 둔 표준 연결 방식. |
| **korean-law MCP** | 법제처(공식 출처)에 연결돼 법령·판례를 실시간 조회하는 MCP. |
| **인용 검증** | AI가 댄 법조문을 공식 원문과 대조해, 맞는 인용만 근거로 남기는 것. |
| **환각** | AI가 사실이 아닌 내용을 사실처럼 지어내는 현상. |

## 8. 직접 만져보며 복습하기 (회차 후)

1. 같은 질문을 **Rerank 적용 전과 후로 비교**해, 참조 문서가 더 정확해졌는지 확인한다.
2. **내부 규정에 분명히 있는 질문**을 던져, 법령 조회 없이 내부 규정 근거로만 답하는지 확인한다(관련도 기준치 이상 분기).
3. **내부 규정에 없는 법령 질문**을 던져, 법제처 법조문을 조회해 근거로 붙이는지 확인한다(관련도 기준치 미만 분기).
4. 일부러 **존재하지 않는 법조문**을 물어, 인용 검증이 "확인되지 않음"으로 걸러 내는지 확인한다.
5. 개선된 화면에서 **답변 복사, 예시 질문 칩, 근거 원문 점프, 출처 뱃지**가 동작하는지 확인한다.
