## 1. 이번 회차가 다루는 3가지

| 주제 | 무엇을 하나 |
|---|---|
| **① Rerank 연결** | 1차 검색으로 넓게 찾은 후보를, 질문과 더 잘 맞는 것만 정밀하게 추려 남긴다. |
| **② 화면(UI) 개선** | 이미 동작하는 대화 화면에, 실무에서 자주 필요한 기능을 더한다. |
| **③ korean-law MCP** | 내부 규정 검색의 관련도가 낮을 때(내부 규정에 마땅한 근거가 없을 때) 대한민국 법령·판례를 공식 출처에서 실시간 조회해 답한다. |

세 가지는 따로 노는 작업이 아니라 **"더 정확한 답"** 이라는 한 가지 목표로 모인다.

> 용어 한 줄 정리
> **RAG**: 우리 데이터베이스에 넣어 둔 문서를 검색해, 그 내용을 근거로 AI가 답하게 하는 방식.
> **임베딩**: 문장을 의미가 담긴 숫자 목록(벡터)으로 바꾼 것. 비슷한 의미일수록 숫자가 가까워, 의미 기반 검색에 쓴다.
> **벡터**: 임베딩이 만들어 낸 숫자 목록. 이 숫자끼리의 거리로 의미가 가까운지 판단한다.

## 2. 주제 ① — 검색 결과 재정렬(Rerank) 연결

### 먼저, 흔한 오해부터 바로잡는다 (가장 중요)

- ❌ **오해**: "검색을 더 잘하려면 임베딩을 OpenAI에서 Cohere로 바꾸고 문서를 다시 색인해야 한다."
- ✅ **사실**: 임베딩은 **OpenAI `text-embedding-3-small`(1024차원)을 그대로 둔다. 바꾸지 않고, 다시 색인하지도 않는다.**

왜 그런가. **임베딩(1차 검색)** 과 **Rerank(재정렬)** 는 서로 **다른 단계**이기 때문이다.

- 임베딩은 문서를 숫자 목록(벡터)으로 바꿔 그 숫자끼리의 거리로 비교한다. 이때 문서를 넣을 때 쓴 도구와 질문을 변환할 때 쓰는 도구가 **같아야** 숫자를 맞대 볼 수 있다. 그래서 임베딩은 OpenAI로 통일해 둔다.
- **Rerank는 벡터(숫자)를 보지 않는다.** **질문 원문(텍스트)과 후보 문서 원문(텍스트)** 을 직접 맞대 보고 점수를 매긴다. 채점 방식이 임베딩과 무관하므로, 임베딩이 OpenAI여도 Rerank는 Cohere로 자유롭게 조합할 수 있다.
- 결론: Rerank는 기존 검색 위에 **거름망 한 단계를 추가**하는 것이지, 기존 검색을 교체하거나 문서를 다시 색인하는 것이 **아니다.**

### 무엇을 하나

1. **1차 검색은 지금 그대로** — OpenAI 임베딩으로 후보를 **넓게 약 30건** 찾는다.
2. **재정렬 단계를 추가** — 그 30건을 **Cohere Rerank** 가 질문과 1:1로 비교해 **상위 8건**만 남긴다.
3. AI는 이제 **정밀하게 추려진 상위 8건**만 받아 답한다.

> **적용 범위 (확정)**: 이번 회차 Rerank는 **`regulation_search`(내부 규정) 검색에만** 연결한다. `documents` 검색에는 적용하지 않고 1차 검색 결과를 그대로 쓴다. 어느 쪽이든 임베딩은 OpenAI 그대로이며 **재색인은 불필요**하다. (③ 분기 신호로 쓰는 관련도 점수도 `regulation_search` 결과에서 나온다.)

> 용어 한 줄 정리
> **Rerank(재정렬)**: 1차 검색으로 모은 후보를, 질문과 각 후보의 **원문 텍스트**를 1:1로 비교해 적합한 순서로 다시 줄 세우는 단계.

### 현재 완성도

- Cohere Rerank를 호출하는 코드(`lib/ai/rerank.ts`)는 **이미 작성되어 있다.**
- 다만 챗 흐름에는 **아직 연결되어 있지 않아**, 지금은 1차 검색 상위 8건을 그대로 사용한다.
- **이번 회차의 핵심 작업 = 이 Rerank 단계를 챗 라우트(`app/api/chat`)의 `regulation_search` 경로에 실제로 연결하는 것이다.** (`documents` 검색은 이번 회차 범위 밖.)

### 왜 하나

규정과 법령은 **정확히 들어맞는 한 조항**이 중요한 분야다. 의미가 대충 비슷한 자료보다 질문에 **정확히 맞는 자료**를 골라 근거로 쓰면 답의 신뢰도가 크게 올라간다. 그래서 후보를 한 번 더 정밀하게 거르는 재정렬의 효과가 크다.

### 끝나면 이렇게 달라진다

- 답변에 **엉뚱한 규정이 섞일 확률**이 줄어든다.
- 답변 아래 "참조 문서"가 **실제 근거에 가까운 것**들로 채워진다.

### 한 가지 더 — Rerank 점수는 "분기 신호"로도 쓴다

Rerank는 각 후보에 **관련도 점수(0~1 사이의 값. % 로 보면 된다)** 를 매긴다. 이 점수는 후보를 줄 세우는 데만 쓰는 게 아니라, **"내부 규정이 이 질문을 제대로 다루고 있는가"** 를 판단하는 신호로도 쓸 수 있다. 상위 결과의 관련도가 높으면 내부 규정에 답이 있다는 뜻이고, 낮으면 내부 규정에 마땅한 근거가 없다는 뜻이다. 이 점수를 ③(법령 조회)의 분기 기준으로 재활용한다(4절에서 설명).

> **분기에 쓰는 점수 (확정)**: 한 건만 보면 우연히 높거나 낮은 값에 휘둘릴 수 있으므로, **Rerank 상위 8건의 관련도 점수 평균**을 분기 신호로 쓴다. 이 평균이 **기준치(기본 0.7 = 70%) 이상이면 내부 규정**으로, **미만이면 법령(MCP)** 으로 분기한다. 기준치는 `.env` 환경변수로 빼서 조정한다(4절).

### ▶ 사용자 프롬프트 — 2장

> 아래 회색 글상자는 **그대로 복사해서 붙여 넣어 쓰는 지시문**이다. 파일 이름이나 기술 용어를 몰라도 된다. 무엇을 원하는지만 또박또박 적으면, 나머지 자세한 부분은 AI가 알아서 처리한다.

> 지금 챗봇이 내부 규정을 찾아서 답하는데, 찾은 자료를 **재정렬(Rerank)로 질문과 더 잘 맞는 순서로 다시 추려서** 답했으면 좋겠어. 내부 규정에서 후보를 넉넉히 찾은 다음, 질문과 각 후보의 **관련도 점수가 높은 위쪽 8개만 골라** 그걸로 답하게 해 줘. 이 **재정렬(Rerank) 기능**은 이미 만들어 둔 게 있으니 새로 만들 필요 없이 그걸 **연결만** 하면 돼. 단, **임베딩으로 후보를 찾는 기본 검색 방식은 바꾸지 말고** 그대로 두고, 이 재정렬은 **내부 규정 검색에만** 적용해 줘. 적용한 뒤에는 **똑같은 질문**을 켜기 전과 켠 후로 넣어서, 답변 아래 '참조 문서'가 어떻게 달라지는지 나란히 보여 줘 — 정말 더 좋아졌는지 눈으로 확인하고 싶어.

## 3. 주제 ② — 챗봇 화면(UI) 개선

대화·답변 표시·근거 표시·스크롤은 이미 동작한다. 이번 회차의 핵심 변화는 **근거(참조 문서)를 보는 방식**이다. 지금은 답변 아래에서 아래로 펼쳐 보는데(아코디언), 이걸 **클릭하면 화면 오른쪽에 원문이 뜨는 '근거 패널'** 로 바꾼다. 내부규정·법령·(나중에)공모공고 세 가지를 한 화면에서 다루려면, 답변을 계속 보면서 옆에서 근거를 확인하는 편이 훨씬 낫기 때문이다.

### 3-1. 이번 회차에 넣을 것

| 후보 | 무엇 | 효과 | 추천도 |
|---|---|---|---|
| **답변 복사 버튼** | AI 답변을 한 번에 복사 | 실무에서 바로 붙여 사용 | 높음 |
| **예시 질문 칩** | 빈 화면에 "이런 걸 물어보세요" 버튼 제시 | 처음 쓰는 사람이 막막하지 않음 | 높음 |
| **근거 → 우측 패널** | 참조 문서를 누르면 **화면 오른쪽에 원문**을 띄움 | 답변 맥락을 유지한 채 근거 확인 | 높음 |
| **출처 뱃지(내부규정/법령)** | 근거가 내부 규정인지 외부 법령인지 표시 | 출처 신뢰도, ③번과 연계 | 높음 |
| **반응형(모바일 바텀시트)** | 좁은 화면에선 근거가 아래에서 올라옴 | 외부·현장·모바일 사용 대비 | 높음 |
| **생성 중단 버튼** | 답변 생성 중 멈추기 | 오답·장문일 때 즉시 끊고 다시 질문 | 높음 |
| **맨 아래로 버튼** | 위로 올려 읽다 최신 답변으로 복귀 | 긴 답변에서 길 잃지 않음 | 높음 |
| **진행 상태 표시** | "내부 규정 찾는 중…/법령 확인 중…" | 기다림 체감 단축, ③ 분기와 연계 | 높음 |
| 대화 저장·이어보기 | 새로고침해도 대화가 유지됨 | 끊김 없는 사용 | 중간 |
| 답변 다시 생성 | 같은 질문을 다시 요청 | 답이 마음에 들지 않을 때 | 중간 |

> **권장 조합**: "답변 복사 + 예시 질문 칩 + **근거 우측 패널(출처 뱃지 포함)** + 반응형" 4가지를 기본으로, **생성 중단 · 맨 아래로 · 진행 상태 표시**를 더한다. 작업량 대비 체감이 크고, 근거 패널·출처 뱃지·진행 상태는 ③(법령 MCP 분기)과 자연스럽게 이어진다. 화면 뒤에서는 **데이터 모양(타입)을 한 곳에 모으는 정리**도 함께 한다(3-6).

### 3-2. 왜 아코디언 대신 '우측 근거 패널'인가

- **맥락이 안 끊긴다**: 아코디언은 펼치면 답변이 아래로 밀려 읽던 흐름이 끊긴다. 패널은 **답변은 그대로 두고 옆에서** 원문을 보여 준다.
- **세 정보원을 제대로 담는다**: 법령은 원문이 길고 '인용 검증 결과'를, 공모공고는 '마감일'을 함께 보여 줘야 한다. 좁은 답변 아래 칸보다 **옆 패널**이 이런 정보를 담기에 알맞다.
- **요즘 방식이다**: 답변 옆에 자료를 펼치는 패널은 Claude의 Artifacts, ChatGPT의 Canvas 등에서 자리 잡은 흐름이고, 답변 본문의 근거 번호를 누르면 해당 원문으로 데려가는 '정밀 인용'은 신뢰를 크게 높인다.

### 3-3. 화면 구성 (넓은 화면 / 좁은 화면)

```
[넓은 화면(PC) — 평소]            [넓은 화면(PC) — 근거를 눌렀을 때]
┌────────────────────────┐        ┌───────────────┬──────────────────┐
│  PIMS Chat             │        │  PIMS Chat    │ 📘 내부규정 [1]   │
│                        │        │               │ 운영규정 제12조    │
│  답변 …근거[1][2]…     │   →    │ 답변 …[1][2]… │ ── 원문 전체 ──   │
│  ┌ 참조문서 2건 ───┐   │        │ ┌참조 2건──┐  │ 출처: ICT-OP-…    │
│  │ 📘[1]  ⚖️[2]    │   │        │ │📘[1] ⚖️[2]│  │ [전체 규정 보기]  │
│  └─────────────────┘   │        │ └──────────┘  │                  │
│  [메시지 입력       ▸] │        │ [입력      ▸] │ (오른쪽 패널)     │
└────────────────────────┘        └───────────────┴──────────────────┘
   패널 닫힘 = 채팅 전체폭            근거 클릭 = 오른쪽에 원문 패널

[좁은 화면(휴대폰) — 근거를 눌렀을 때]
┌──────────────┐
│  PIMS Chat   │   근거를 누르면 화면을 가르지 않고
│  답변 …[1]…  │   아래에서 '바텀시트'가 올라와 원문을 덮어 보여 줌
│ ┌─참조 2건─┐ │   (위로 쓸어내리거나 X로 닫음)
│ ╞══════════╡ │
│ │📘 내부규정 │ │  ← 아래에서 올라온 시트
│ │운영규정…   │ │
│ └──────────┘ │
└──────────────┘
```

- **넓은 화면(PC, 대략 노트북 이상)**: 오른쪽에 패널이 갈라져 뜬다. 답변과 원문을 나란히 본다.
- **좁은 화면(휴대폰·태블릿)**: 화면을 가르지 않고 **아래에서 시트가 올라와** 원문을 덮는다. 닫으면 다시 대화로 돌아온다.
- 공통: **한 번에 하나의 근거**만 열고, 본문의 근거 번호 `[1] [2]`를 누르면 패널이 그 근거로 바로 이동한다.

### 3-4. 근거 종류에 따라 패널 내용이 다르다 (출처 혼동 방지)

근거가 **내부규정인지·법령인지·공모공고인지**를 색과 내용으로 분명히 구분한다. 이게 통합 챗봇에서 가장 중요한 안전장치다.

| 근거 종류 | 뱃지 | 패널에 보여 줄 것 |
|---|---|---|
| **📘 내부규정** | 파랑 | 조문 본문 + 내부문서번호(예: ICT-OP-2024-008) + "전체 규정 보기" |
| **⚖️ 법령** | 보라 | 조문 원문 + **인용 검증 결과(✓ 검증됨 / ⚠️ 확인되지 않음)** + 시행일·개정일 + 법제처(law.go.kr) 원문 링크 |
| **📋 공모공고**(8월 추가) | 초록 | **접수 D-n / 마감됨** + 기관·신청자격 요약 + 공고 원문 링크 |

> 이번 회차는 **📘 내부규정 · ⚖️ 법령** 2종만 만든다. 📋 공모공고는 8월 크롤러가 붙을 때 **같은 패널에 카드 한 종류만 추가**하면 되도록 미리 구조를 맞춰 둔다.

### 3-5. 더 매끄럽게 — 생성 중단 · 맨 아래로 · 진행 상태

사용자가 답변을 기다리고 읽는 동안의 작은 불편을 세 가지 더 없앤다. 외부 기관 담당자(비전문가)가 쓰는 화면이라, 이런 작은 매끄러움이 신뢰로 이어진다.

| 기능 | 무엇을 | 왜 |
|---|---|---|
| **생성 중단** | 답변이 만들어지는 동안 **전송 버튼이 '중단'으로 바뀌고**, 누르면 즉시 멈춤 | 답이 길거나 엉뚱하게 흐를 때 끝까지 기다리지 않고 바로 다시 질문. 불필요한 비용도 절감 |
| **맨 아래로** | 답변이 길어 위로 올려 읽다가, 새 글이 계속 이어지면 **'↓ 최신 답변으로' 버튼**이 떠서 한 번에 복귀 | 긴 답변·법령 원문에서 현재 위치를 잃지 않음 |
| **진행 상태** | 답이 나오기 직전, 지금 무얼 하는지 **"내부 규정 찾는 중… / 법령 확인 중…"** 한 줄로 표시 | 빈 화면 대기 체감을 줄임. ③ 분기(내부규정 ↔ 법령)가 **어느 쪽으로 갔는지**도 자연스럽게 드러남 |

> **진행 상태는 ③(법령 분기)와 한 묶음이다.** 화면이 "지금 법령 확인 중"이라고 말하려면, **서버가 단계 신호(검색 중 → 재정렬 중 → 법령 조회 중)를 함께 보내 줘야** 한다. 그래서 이 표시는 4절의 분기 작업과 같이 만든다(파일 맵 7절 참조).

### 3-6. 뒤에서 한 번 정리 — '데이터 모양' 한 곳에 모으기 (공용 타입)

화면에는 안 보이지만, 이번에 같이 해 두면 좋은 **정리 작업**이 하나 있다.

- **지금 상태**: 답변·근거가 어떤 모양(제목·내용·출처·점수…)인지를 **화면 쪽과 서버 쪽이 각자 따로** 적어 두고 있다. 같은 양식을 두 군데에 베껴 쓰는 셈이다.
- **무엇이 문제냐**: 한쪽만 고치면 서로 어긋나 버그가 난다. 특히 이번에 근거에 **'출처 종류(내부규정/법령)' 표시를 새로 더하면** 양쪽을 동시에 고쳐야 하는데, 한쪽을 빠뜨리기 쉽다.
- **무엇을 하나**: 이 '데이터 모양' 정의를 **한 파일에 모아 두고 화면·서버가 똑같이 가져다 쓰게** 한다. 출처 종류를 추가하는 김에 같이 정리하면 가장 깔끔하다.

> 비유: 같은 신청서 양식을 부서마다 따로 복사해 쓰면 언젠가 칸이 어긋난다. **양식 원본을 한 곳에 두고 모두 그걸 참조**하게 만드는 정리다. 사용자 화면은 그대로지만, 앞으로의 실수가 줄어든다.

### ▶ 사용자 프롬프트 — 3장

> 아래 회색 글상자는 **그대로 복사해 붙여 넣어 쓰는 지시문**이다. 파일 이름이나 기술 용어는 몰라도 된다. 한 개씩 차례로 시켜도 되고, 한꺼번에 붙여도 된다.

> 챗봇 화면을 더 쓰기 편하게 다듬어 줘. ① 답변마다 **'복사' 버튼**이 있어 한 번에 복사되게, ② 대화가 비어 있을 때 **'이런 걸 물어보세요' 예시 질문 버튼** 몇 개가 뜨게, ③ 답변 아래 참조 문서를 누르면 **화면 오른쪽에 그 원문이 뜨게**, ④ 각 근거 옆에 **'내부규정'인지 '법령'인지 한눈에 보이는 색 표시(뱃지)**를 붙여 줘. 지금 잘 되는 대화·답변 기능은 **그대로 두고** 위 4가지만 더해 줘.

> 근거를 볼 때 답변이 아래로 밀려 흐름이 끊기지 않게, **답변은 그대로 둔 채 화면 오른쪽에 원문 패널**이 열리게 해 줘. 답변 본문에 있는 근거 번호 **`[1] [2]`를 누르면** 그 번호의 원문으로 패널이 바로 이동하고, **한 번에 하나만** 열리며, **X나 바깥을 누르면 닫히게** 해 줘.

> 근거 종류에 따라 패널 내용을 다르게 보여 줘. **내부규정**이면 조문 본문과 내부문서번호를, **법령**이면 조문 원문과 함께 **'✓ 검증됨' 또는 '⚠️ 확인되지 않음'** 표시·시행일·법제처 원문 링크를 보여 주고, 종류별로 **뱃지 색을 다르게**(내부규정=파랑, 법령=보라) 해서 한눈에 구분되게 해 줘.

> 화면 크기에 따라 자연스럽게 바뀌게 해 줘. **넓은 화면(노트북·PC)에선 오른쪽에 패널이 갈라져** 답변과 원문을 나란히 보고, **좁은 화면(휴대폰)에선 화면을 가르지 말고 아래에서 시트가 올라와** 원문을 덮어 보여 주게. 닫으면 다시 대화로 돌아오게 해 줘.

> (나중에 쓸 것) 8월에 공모사업 공고가 추가되면, **같은 오른쪽 패널에 '공고 카드' 한 종류만 더** 넣을 수 있게 지금 구조를 만들어 둬. 공고 카드는 **접수 마감일(D-n)** 과 신청자격 요약, 공고 원문 링크를 보여 줄 거야.

> 답변이 만들어지는 동안에는 **'전송' 버튼이 '중단' 버튼으로 바뀌게** 하고, 그걸 누르면 **만들던 답변을 즉시 멈추게** 해 줘. 멈춘 뒤에는 바로 다음 질문을 입력할 수 있어야 해.

> 답변이 길어서 위로 스크롤해 읽고 있을 때, 새 내용이 계속 이어지면 화면 한쪽에 **'↓ 최신 답변으로' 버튼**이 떠서, 누르면 **맨 아래(가장 최근 내용)로 한 번에** 내려가게 해 줘. 맨 아래에 있을 때는 그 버튼이 안 보이게 하고.

> 답이 시작되기 전에 **지금 무엇을 하는 중인지 한 줄로 보여 줘.** 내부 규정을 찾는 동안엔 "내부 규정 찾는 중…", 법령을 확인하는 동안엔 "법령 확인 중…" 처럼. (이건 답을 만드는 서버 쪽에서 **지금 단계가 무엇인지 신호를 같이 보내 줘야** 화면에 표시할 수 있어. 그 신호도 함께 만들어 줘.)

> 화면(프런트)과 답을 만드는 서버가 **주고받는 데이터의 모양(답변·근거·출처 종류 같은 것)을 한 곳에 모아 두고**, 양쪽이 똑같이 그걸 가져다 쓰게 정리해 줘. 지금은 같은 모양을 두 군데에 따로 적어 두고 있는데, 출처 종류(내부규정/법령)를 새로 더하는 김에 한 곳으로 합쳐서 **나중에 한쪽만 고쳐 어긋나는 일이 없게** 해 줘. 화면 동작은 그대로 유지하고.

## 4. 주제 ③ — 법령 실시간 조회(korean-law MCP)

### MCP가 무엇인가

> 용어 한 줄 정리
> **MCP(Model Context Protocol)**: AI(Claude)가 외부 도구·자료에 직접 접속하도록 정해 둔 표준 연결 방식.
> **korean-law MCP**: 그 연결이 **법제처(law.go.kr)**, 즉 대한민국 법령·판례의 공식 출처에 닿아 있는 MCP. 이를 통해 법령을 실시간으로 조회한다.

### korean-law MCP가 할 수 있는 일

| 할 수 있는 것 | 쉽게 말하면 |
|---|---|
| 법령 검색 | "전자금융거래법" 같은 법을 찾기 |
| 법령 조문 원문 가져오기 | 특정 조문의 **정확한 원문 텍스트** 받기 |
| 판례 검색·원문 | 관련 판례를 찾고 내용 보기 |
| 별표·서식 | 법에 딸린 표·서식 받기 |
| **인용 검증** | AI가 "○○법 제○조"라고 했을 때, 그것이 실제와 맞는지 **공식 원문과 대조** |
| 개정 추적 | 그 조항이 언제 어떻게 바뀌었는지 확인 |

### 내부 규정(RAG) vs 법령(MCP)

| | 내부 규정 (우리 데이터베이스·RAG) | 법령·판례 (korean-law MCP) |
|---|---|---|
| 어디 있나 | 우리가 직접 넣은 문서 | 법제처 공식 서버 |
| 최신성 | 우리가 직접 갱신해야 함 | 실시간 조회라 항상 최신 |
| 정확성 | 조각 단위로 저장해 일부 누락 가능 | 공식 원문 그대로 |
| 적합한 용도 | 우리 기관 내부 규정·지침 | 자주 바뀌는 외부 법령·판례 |

핵심: 근거는 **내부 규정(우리 데이터베이스·RAG)** 과 **법령·판례(법제처·MCP)** 두 갈래가 있고, 질문마다 관련도에 따라 **둘 중 하나를 골라** 답한다(분기 방식은 바로 아래에서 설명). 법령은 자주 바뀌고 정확한 원문이 중요하므로, 우리가 복사해 두기보다 그때그때 공식 출처에서 실시간으로 받아오는 것이 안전하다.

### 언제 내부 규정으로, 언제 법령으로? — 관련도 기준 분기

이번 회차의 핵심 설계다. 내부 규정과 법령을 **항상 동시에 합쳐 쓰지 않는다.** 대신 **내부 규정 검색의 관련도 점수를 기준으로 둘 중 하나로 분기**한다. 먼저 용어부터 정리한다.

> 용어 한 줄 정리
> **관련도 점수**: Rerank가 상위 후보에 매긴 0~1 사이의 점수(% 로 보면 된다). 질문과 그 문서가 얼마나 잘 맞는지를 나타낸다.
> **기준치(threshold)**: 분기를 가르는 경계값. 이 값 이상이면 "내부 규정에 있다", 미만이면 "내부 규정에 없다"로 본다.
> **분기(라우팅)**: 조건에 따라 처리 경로를 둘 중 하나로 가르는 것.

처리 규칙은 다음과 같다.

1. 질문이 들어오면 **먼저 내부 규정을 1차 검색 → Rerank** 한다(2절의 ①). 이때 **상위 8건의 관련도 점수**가 나온다.
2. 그 **상위 8건의 관련도 평균**을 구한다. **평균이 기준치 이상이면** = 내부 규정이 이 질문을 다루고 있다고 본다 → **내부 규정만 근거로** AI가 추론해 답한다. (법령 조회는 하지 않는다.)
3. **평균이 기준치 미만이면** = 내부 규정에 마땅한 근거가 없다고 본다 → **korean-law MCP로 법령·판례를 실시간 조회**해, 그것을 근거로 답한다.

| 상위 8건 관련도 평균 | 판단 | 근거로 쓰는 것 |
|---|---|---|
| 기준치 **이상** | 내부 규정에 있음 | 내부 규정(RAG) 결과만 |
| 기준치 **미만** | 내부 규정에 없음 | korean-law MCP로 받은 법령·판례 |

#### 기준치와 점수 기준 (확정)

- **점수 기준**: 한 건만 보면 우연히 튀는 값에 흔들리므로, **Rerank 상위 8건의 관련도 점수 평균**으로 본다.
- **기준치(threshold)**: **기본 0.7(= 70%)**. 평균이 0.7 이상이면 내부 규정, 미만이면 법령으로 분기한다.
- **조정 방법**: 기준치는 코드에 박지 않고 **`.env` 환경변수로 빼서** 실제 질문으로 맞춰 가며 바꾼다. 너무 높이면 내부 규정에 있는데도 법령을 부르고, 너무 낮추면 내부 규정에 없는데도 억지로 내부 규정으로 답하려 한다.

```bash
# .env.local — 어드바이저 분기 설정
RETRIEVAL_TOP_K=30        # (기존) 1차 검색으로 넓게 가져오는 후보 수
RERANK_TOP_K=8            # (기존) Rerank 상위 건수 = 관련도 평균을 낼 대상
RELEVANCE_THRESHOLD=0.7   # (신규) 분기 기준치. 상위 8건 평균 관련도 ≥ 0.7 이면 내부 규정으로 답
```

> `RETRIEVAL_TOP_K`(30)·`RERANK_TOP_K`(8)는 `lib/env.ts`에 **이미 정의되어 있다.** 이번 회차에 새로 추가할 변수는 **`RELEVANCE_THRESHOLD`(분기 기준치) 하나뿐**이다.

법령으로 분기된 경우, MCP로 받은 조문은 **인용 검증**을 거쳐 실제와 맞는지 확인한 뒤 답의 근거로 쓴다. 답에는 그 근거가 **내부규정인지 법령인지 출처를 구분해 표시**한다(아래 "출처 표시 규칙").

#### 출처 표시 규칙 (확정)

- 답변 본문과 **참조 문서(근거 목록) 영역**에, 각 근거가 **`내부규정`** 인지 **`법령`** 인지 **출처 타입을 함께 표기**한다.
- 화면에서는 출처 뱃지로 구분한다: **📘 내부규정 / ⚖️ 법령**. (8월 공모 공고가 들어오면 **📋 공모공고**가 추가된다 — 7절 참조.)
- 예) 참조 문서
  - `📘 내부규정` ICT기금 운영규정 제12조 제2항 (출처: ICT-OP-2024-008)
  - `⚖️ 법령` 국가재정법 제54조 (법제처, 인용 검증 통과)

### 인용 검증으로 환각 막기

> 용어 한 줄 정리
> **환각**: AI가 실제로는 없는 내용을 사실처럼 그럴듯하게 지어내는 현상.
> **인용 검증**: AI가 댄 "○○법 제○조"를 공식 원문과 대조해, 실제로 존재하고 맞는 인용만 근거로 남기는 것.

법령 챗봇에서 가장 큰 위험은 AI가 **있지도 않은 조항**을 그럴듯하게 지어내는 것이다. korean-law MCP의 인용 검증으로 AI가 댄 법조문을 공식 원문과 대조하면, 사실인 것만 근거로 남기고 지어낸 것은 거를 수 있다.

### ▶ 사용자 프롬프트 — 4장

> 챗봇이 질문을 받으면 **먼저 우리 내부 규정에서** 답을 찾아보게 해 줘. 찾은 자료 중 **재정렬(Rerank) 상위 8건의 관련도 점수(0~1) 평균**을 따져서, **기준치 이상이면** 내부 규정만으로 답하고, **미만이면** 그 질문은 우리 규정에 마땅한 답이 없는 거니까 **법제처(법령 공식 출처)에서 관련 법을 실시간으로 찾아와** 그걸 근거로 답하게 해 줘. '얼마나 잘 맞아야 충분한가'를 가르는 **기준선은 나중에 내가 직접 쉽게 바꿀 수 있게** 따로 설정값으로 빼 주고(처음엔 0.7=70%쯤으로), 이 기준을 조금씩 높였다 낮췄다 하면서 같은 질문들을 다시 돌려, 어떤 질문이 내부 규정으로 답하고 어떤 질문이 법령으로 넘어가는지 비교해서 보여 줘 — 어느 선이 제일 자연스러운지 정하고 싶어.

> 법령으로 답할 때는, AI가 "○○법 제○조"라고 말한 게 **진짜 있는 조문인지 법제처 공식 원문과 대조(인용 검증)**해서 **맞는 것만** 근거로 보여 줘. 대조해도 확인이 안 되는 건 **AI가 지어낸 환각**일 수 있으니 슬쩍 넘기지 말고 **"확인되지 않음"이라고 솔직하게** 표시하고. 그리고 답변 아래 근거 목록에는 각 근거가 우리 **내부 규정에서 온 건지(📘 내부규정)**, **법령에서 온 건지(⚖️ 법령)** 한눈에 색으로 구분되게 표시해 줘.

## 5. 셋을 합친 전체 처리 흐름

1. 사용자가 질문을 입력한다.
2. 내부 규정을 1차 검색해 후보를 약 30건 찾는다. (`regulation_search`, OpenAI 임베딩, 그대로)
3. 그 30건을 Cohere Rerank로 재정렬해 상위 8건만 남기고, 그 **상위 8건의 관련도 점수 평균**을 구한다. (①)
4. **상위 8건 관련도 평균으로 분기한다.** (③)
   - 평균 **≥ 기준치(기본 0.7, `.env`로 조정)** → 내부 규정에 답이 있다고 보고, **내부 규정 근거만**으로 답한다. (법령 조회 안 함)
   - 평균 **< 기준치** → 내부 규정에 없다고 보고, **korean-law MCP로 법령·판례를 조회**하고 인용 검증을 거쳐 그것을 근거로 쓴다.
5. AI(Claude)가 선택된 근거(내부 규정 또는 검증된 법령)로 답을 작성하고, 실시간으로 한 글자씩 이어 보여 준다(스트리밍).
6. 개선된 화면에 표시한다. 답변 복사, 예시 질문 칩, **근거 클릭 시 우측 근거 패널**(좁은 화면은 바텀시트), **출처 뱃지(📘 내부규정 / ⚖️ 법령)** — 참조 문서에 출처 타입 표기. (②)

요약하면, 더 정확하게 찾고(①), 관련도에 따라 내부 규정과 법령 중 맞는 근거로 답하고(③), 더 쓰기 좋게 보여 준다(②).

## 8. 향후 방향 — 3개 정보원 통합 (규정·법령·공모)

이번 회차에서 **내부규정(RAG) + 법령(MCP)** 2개 정보원을 분기·통합하는 패턴을 만든다. 이 패턴은 그대로 확장되어, 최종적으로 **3개 정보원**을 같은 챗봇 화면에서 답하게 된다. (근거: `docs/04-feature-advisor.md` 7장)

### 3개 정보원과 찾는 방식

| 정보원 | 어디서 / 어떻게 | 핵심 |
|---|---|---|
| **📘 내부규정 (RAG)** | 우리 DB(`documents`·`regulation`) — OpenAI 임베딩 검색 + Cohere 재정렬 | 기관 권위 문서 |
| **⚖️ 법령 (MCP)** | 법제처 — korean-law MCP 실시간 조회 + 인용 검증 | 최신성·정확 원문 |
| **📋 공모사업공고 (Crawling)** | 우리 DB(`announcements`) — ② 크롤러가 적재 → 내부규정과 **같은 임베딩 검색** | **시의성**(접수·마감일) |

> 핵심 구분: **내부규정과 공모공고는 같은 방식**(우리 DB 임베딩 검색)이라 통합이 쉽다. **법령만 외부 실시간 조회**라 통합의 관건이다.

### 통합 방식 — "골라서 부르는" 라우팅

세 정보원을 매번 다 부르면 느리고 비싸고 출처가 뒤섞인다. 그래서 **질문에 필요한 정보원만 고른다.** 이번 회차의 **관련도 분기를 그대로 확장**한 형태다.

- **단순 질문** → 분기 + 단일 검색(빠른 경로).
- **복합 질문**("이 공모가 우리 규정상 신청되나?" 등) → 도구 호출(tool use)로 여러 정보원을 차례로/병렬 조회.
- 공모 검색은 내부 검색 단계에 **테이블(`announcements`)만 추가**하면 라우팅에 자연스럽게 들어온다.

### 단계별 도입 (로드맵)

1. **이번 회차(6월)** — 내부규정 RAG + 재정렬 + 관련도 분기 + 법령(MCP) → **2개 정보원 통합 + 출처 뱃지** 패턴 검증.
2. **8월** — 크롤러가 `announcements` 적재 → `search_announcements` 추가 → 라우터에 **3번째 정보원(공모공고) 등록** + 공고 신선도(접수 D-n / 마감) UX.
3. **이후** — 복합 질문용 도구 호출 오케스트레이션 정교화 + 관리자 로그의 분기·정보원 통계로 라우팅 품질 튜닝.

> 한 번에 셋을 다 붙이지 않는다. **2개 정보원으로 통합 패턴(라우팅·출처 구분)을 검증한 뒤** 공모 공고를 끼워 넣는 것이 위험이 가장 낮다. 그래서 이번 회차의 **출처 뱃지(📘 내부규정 / ⚖️ 법령)** 설계가 8월의 **📋 공모공고**까지 그대로 이어지도록 미리 맞춰 둔다.

## 9. 핵심 용어 (한 줄 정의)

| 용어 | 한 줄 설명 |
|---|---|
| **Rerank(재정렬)** | 후보를 질문과 1:1로 비교해 다시 줄 세우는 단계. **벡터가 아닌 원문 텍스트**로 채점하므로 임베딩과 독립이다. |
| **1차 검색 vs Rerank** | 1차 검색은 OpenAI 임베딩으로 넓게(약 30건) 찾는 단계, Rerank는 Cohere로 정밀하게(약 8건) 추리는 단계. 서로 다른 단계라 임베딩 교체·재색인이 필요 없다. |
| **관련도 점수** | Rerank가 후보에 매기는 0~1 사이 점수(% 로 봐도 된다). 질문과 문서가 얼마나 맞는지를 나타낸다. |
| **기준치(threshold)** | 내부 규정으로 답할지 법령으로 넘길지 가르는 관련도 경계값. |
| **분기(라우팅)** | 관련도 점수에 따라 처리 경로를 내부 규정 또는 법령(MCP) 중 하나로 가르는 것. |
| **MCP** | AI가 외부 도구·자료에 직접 접속하도록 정해 둔 표준 연결 방식. |
| **korean-law MCP** | 법제처(공식 출처)에 연결돼 법령·판례를 실시간 조회하는 MCP. |
| **인용 검증** | AI가 댄 법조문을 공식 원문과 대조해, 맞는 인용만 근거로 남기는 것. |
| **환각** | AI가 사실이 아닌 내용을 사실처럼 지어내는 현상. |

## 10. 직접 만져보며 복습하기 (회차 후)

1. 같은 질문을 **Rerank 적용 전과 후로 비교**해, 참조 문서가 더 정확해졌는지 확인한다.
2. **내부 규정에 분명히 있는 질문**을 던져, 법령 조회 없이 내부 규정 근거로만 답하는지 확인한다(상위 8건 평균 ≥ 0.7 분기).
3. **내부 규정에 없는 법령 질문**을 던져, 법제처 법조문을 조회해 근거로 붙이는지 확인한다(상위 8건 평균 < 0.7 분기).
4. 일부러 **존재하지 않는 법조문**을 물어, 인용 검증이 "확인되지 않음"으로 걸러 내는지 확인한다.
5. 개선된 화면에서 **답변 복사, 예시 질문 칩, 근거 우측 패널(모바일은 바텀시트), 출처 뱃지**가 동작하는지 확인한다.
6. **생성 중단** 버튼으로 답변을 도중에 멈출 수 있는지, 답이 나오기 전 **진행 상태**("내부 규정 찾는 중…/법령 확인 중…")가 뜨는지, 긴 답변에서 **'↓ 최신 답변으로'** 버튼이 동작하는지 확인한다.
