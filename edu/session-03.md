## 1. 큰 그림 업데이트 (식당 비유 확장)

2회차의 식당 비유를 기억하자: 손님(사용자) → 점원(화면) → 주방(서버) → 창고(검색) + 요리사(AI).
3회차는 여기에 **사람과 시설을 더 붙인다.**

```
손님 ──질문──► 점원(화면, ②개선)──► 주방(서버)
                                        │
                ┌───────────────────────┼───────────────────────┐
                │                        │                       │
        ① 창고에서 넓게 찾기      ① 사서가 정밀하게 추림    ③ 옆 건물 "법령 도서관"에
        (임베딩 검색 30건)  ──►  (Rerank로 8건 엄선)        직접 전화해 최신 법조문 받기
                                        │                  (korean-law MCP)
                                        ▼
                              요리사(AI)가 엄선된 자료 + 법령으로 답 작성
                                        │
손님 ◄──실시간으로──  점원  ◄────────────┘
```

- **① 사서(Rerank)** 고용 → 창고에서 대충 뽑은 것을 한 번 더 정밀하게 거른다.
- **③ 법령 도서관(korean-law MCP)** 직통 연결 → 우리 창고에 없는 **최신 법령·판례**를 외부에서 실시간으로 가져온다.
- **② 점원(화면)** 도 더 친절하게 응대하도록 손본다.

## 2. 주제 ① — Rerank(재정렬) 붙이기 = "사서 고용"

2회차 5장에서 배운 그 "사서"를 이번에 실제로 붙인다.

### 무엇을 하나

1. **검색 도구를 Cohere로 교체** — 1회차에서 문서를 넣을 때 쓴 OpenAI를, 한국어에 더 강한 **Cohere**로 바꾼다.
   - ⚠️ **짝 맞추기 규칙(1회차 핵심)**: 문서를 넣을 때 쓴 도구와, 질문을 검색할 때 쓰는 도구는 **반드시 같아야** 한다.
   - 그래서 도구를 바꾸면 **기존 문서를 Cohere로 다시 정리(재색인)** 해야 한다. (이걸 빠뜨리면 검색이 헛돈다.)
2. **재정렬 단계 추가** — 검색으로 **넓게 30건** 찾고 → Cohere 재정렬로 **정밀하게 8건** 만 남긴다.
3. AI는 이제 **엄선된 8건**만 받아 답한다.

### 왜 하나 (한 문장)

> 규정·법령은 **"정확한 한 조항"** 이 중요한 분야라, 대충 비슷한 자료보다 **딱 맞는 자료**를 골라주는 재정렬의 효과가 크다.

### 끝나면 이렇게 달라진다

- 답변에 **엉뚱한 규정이 섞일 확률**이 줄어든다.
- 답 아래 "참조 문서"가 **진짜 근거다운 것**들로 채워진다.

### Claude에게 시킬 일 (예시 지시)

- "문서 색인과 질문 검색을 **OpenAI에서 Cohere `embed`로 교체**해줘. 기존 문서는 **Cohere로 재색인**하는 스크립트도 만들어줘."
- "검색을 **30건 찾은 뒤 Cohere `rerank`로 상위 8건만** 남기도록 바꿔줘."

## 3. 주제 ② — AI 챗봇 UI 개선 (후보 메뉴, 골라서 진행)

2회차에서 대화·스트리밍·근거·스크롤은 됐다. 이제 **"쓰다 보면 아쉬운 것"** 을 채운다.
아래는 후보다. 이번 회차에 **무엇을 넣을지 고르자.** (전부 할 필요 없음)

| 후보 | 무엇 | 효과 | 추천도 |
|---|---|---|---|
| **답변 복사 버튼** | AI 답을 한 번에 복사 | 실무에서 바로 붙여 씀 | ⭐ 높음 |
| **예시 질문 버튼** | 빈 화면에 "이런 걸 물어보세요" 칩 | 첫 사용자가 막막하지 않음 | ⭐ 높음 |
| **근거 → 원문 점프** | 참조 문서 클릭 시 해당 규정/법령 원문으로 | 신뢰·검증 강화 | ⭐ 높음 |
| **대화 저장/이어보기** | 새로고침해도 대화 유지 | 끊김 없는 사용 | 중간 |
| **답변 다시 생성** | 같은 질문 재요청 | 마음에 안 들 때 | 중간 |
| **모바일 화면 정리** | 좁은 화면 대응 | 외부 사용 대비 | 중간 |
| **법령/규정 출처 구분 표시** | 근거가 "내부규정"인지 "법령"인지 뱃지 | ③번과 짝 (출처 신뢰) | ⭐ (③ 연계) |

> 👉 **권장 조합**: "답변 복사 + 예시 질문 + 근거 원문 점프 + 출처 구분 뱃지" 4개.
> 작업량 대비 체감이 크고, ③(법령 MCP)과 자연스럽게 이어진다.

## 4. 주제 ③ — korean-law MCP = "법령 도서관 직통 전화"

### MCP가 뭔가 (아주 쉽게)

- **MCP(Model Context Protocol)** = AI(Claude)가 **외부 도구·자료에 직접 연결**하도록 표준화한 "콘센트" 같은 것.
- 비유: Claude에게 **전용 전화선**을 깔아주는 것. 그 전화선으로 법령 도서관에 직접 전화를 건다.
- **korean-law MCP** = 그 전화선이 연결된 곳이 **법제처(law.go.kr)**, 즉 **대한민국 법령·판례의 공식 출처**다.

### korean-law MCP가 해주는 일

| 할 수 있는 것 | 쉽게 말하면 |
|---|---|
| 법령 검색 | "전자금융거래법" 같은 법을 찾기 |
| 법령 원문 가져오기 | 특정 조문 **전체 정확한 텍스트** 받기 |
| 판례 검색·원문 | 관련 판례 찾고 내용 보기 |
| 별표·서식 | 법에 딸린 표·서식 받기 |
| **인용 검증** | AI가 "OO법 제5조"라 했을 때, **그게 진짜 맞는지 대조** |
| 개정 추적 | 그 조항이 **언제 어떻게 바뀌었는지** |

### 왜 RAG(우리 DB 검색) 말고 MCP를 쓰나

| | 내부 규정 (우리 DB·RAG) | 법령·판례 (korean-law MCP) |
|---|---|---|
| 어디 있나 | 우리가 직접 넣은 문서 | 법제처 공식 서버 |
| 최신성 | 우리가 갱신해야 함 | **항상 최신 (실시간 조회)** |
| 정확성 | 청크 단위라 일부 누락 가능 | **공식 원문 그대로** |
| 적합한 용도 | 우리 기관 내부 규정·지침 | 바뀌는 외부 법령·판례 |

> 핵심: **내부 규정은 우리 창고(RAG)에서, 외부 법령은 공식 도서관(MCP)에서.** 둘을 합쳐 답한다.
> 법령은 **자주 바뀌고 정확한 원문이 중요**해서, 우리가 베껴두는 것보다 **그때그때 공식 출처에서 받아오는 게** 안전하다.

### 챗봇에 어떻게 합쳐지나

```
질문: "전자금융거래법상 정산 기한이 우리 내부 규정과 다른가?"
        │
        ├─► 내부 규정 검색(RAG + Rerank)  →  우리 정산 지침 8건
        │
        └─► korean-law MCP                →  전자금융거래법 해당 조문 원문
                                              + 인용 검증(진짜 그 조문 맞는지)
        │
        ▼
  AI가 둘을 종합 → "내부 규정은 X일, 법령은 Y일. 차이는 …" + 근거(규정/법령) 표시
```

### 환각(없는 말 지어내기) 방지 — 인용 검증

- 법령 챗봇의 가장 큰 위험: AI가 **있지도 않은 조항**을 그럴듯하게 지어내는 것.
- korean-law MCP의 **인용 검증**으로, AI가 댄 "○○법 제○조"를 **공식 원문과 대조**해 사실인지 확인할 수 있다.
- → 2회차의 "근거 표시"가 한 단계 진화: **근거를 보여줄 뿐 아니라, 그 근거가 진짜인지 검증.**

### Claude에게 시킬 일 (예시 지시)

- "korean-law MCP를 챗봇에 연결해서, **법령 관련 질문이면 법제처에서 조문 원문을 가져와** 답변 근거로 쓰게 해줘."
- "AI가 인용한 법조문은 **인용 검증을 거쳐** 사실인 것만 근거에 표시해줘."

> 📌 참고: 1회차 설계 메모에는 법령을 "자체 구현"으로 처리한다는 방향이 있었다.
> 이번에 **korean-law MCP 사용으로 방향을 바꾸는 것**이라, 확정되면 설계 문서(`docs/`)도 함께 업데이트해야 한다.

## 부록. 직접 만져보며 복습하기 (회차 후)

1. 같은 질문을 **Rerank 적용 전/후로 비교** → 참조 문서가 더 정확해졌는지 보기.

4. 개선된 UI에서 **복사·예시질문·근거 점프** 동작해보기.
