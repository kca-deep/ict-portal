# RAG·법령 라우팅 안정화 설계

> 일자: 2026-06-29 · 대상: `app/api/chat/route.ts` + `lib/ai/llm-router.ts` + `lib/law/` + `prompts/prompts.md`
> 기준 HEAD: `f0ff609` (main) · 상태: 설계 확정(조치 전)
> 선행 진단: `edu/improve-rag.md`, 본 세션 프로덕션 실측(3000 포트)

## 1. 문제 정의

같은 의도의 질문이 입력 토큰 하나로 정상/오류가 갈리는 **경계 의존적 라우팅 버그**.

- `ict기금 전담기관이란` → `regulation` (정상, 규정 제3조 정의 인용)
- `ict 전담기관이란` → `law` (오류, 가상융합산업법·연구산업진흥법 등 ICT기금 무관 법령 표면화 + 거짓 환각 플래그)

근본 원인은 **`isRegulationSufficient` LLM 게이트**. "규정에 축자 정의가 안 잡힘"을 "법령이 필요함"으로 오인하고, 그 판정 입력(top-K 재정렬 청크)이 불안정해 토큰에 민감하게 뒤집힌다.

## 2. 수용 기준 (3 시나리오)

로컬 테스트 3유형이 곧 acceptance test다.

| 유형 | 기대 동작 | 라우트 |
|---|---|---|
| **A. 규정관련** | 내부 규정으로 답변 + 규정 출처만 | `regulation` |
| **B. 규정외(in-scope 법령)** | 법령으로 답변 + 검증된 법령 출처만 | `law` |
| **C. 전혀 무관** | 정중히 거절, 출처 없음 | (scope 거절) |

## 3. 실측 근거 (규정 maxScore 전수)

프로덕션 8질의 실측. 규정 maxScore가 A/B를 깨끗이 가른다.

| 질의 | 유형 | 규정 maxScore | 현재 라우트 | 비고 |
|---|---|---|---|---|
| 중간보고서 절차 | A | **0.688** | regulation | ✅ |
| ict기금 전담기관이란 | A | **0.655** | regulation | ✅ |
| ict 전담기관이란 | A | **0.504** | **law** | ❌ 게이트 오발 |
| 기업회생 절차 | B | **0.192** | law | ✅ 라우팅(노이즈·표시 결함) |
| 개인정보 유출 신고 | B | **0.105** | law | ✅ (거짓 halluc) |
| 하도급 대금 미지급 | B | **0.057** | law | ✅ |
| 육아휴직 기간 | B | **0.034** | law | ✅ |
| 오늘 날씨 | C | — | 거절 | ✅ |

**A형 최저 0.504 vs B형 최고 0.192 → 0.31 폭의 빈 구간.** 임계값을 그 사이에 두면 LLM 게이트 없이 A/B가 안정 분리된다.

## 4. 설계 결정

### 4.1 핵심: 불안정 게이트 → 안정 임계값 교체

- `RELEVANCE_THRESHOLD` 0.15 → **0.33** (env 유지, 튜닝 가능)
- `routedToLaw = !outOfScope && belowThreshold` 로 단순화 — **`isRegulationSufficient`의 law 라우팅 제거**
- 결과: 전담기관(0.504·0.655) → 규정 복귀(버그 해소), 기업회생 → 법령 정주행, 날씨 → scope 거절

**임계값 마진 (재측정 반영)**: 기업회생 규정 maxScore는 재정렬 비결정성으로 **0.192~0.300 사이를 오감**(2회 관측). A형 최저는 0.504. 0.33은 B 상단(0.300) 위 마진 0.03, A 하단(0.504) 아래 마진 0.17. B 마진이 얇으므로 실트래픽 `query_log` score 분포로 0.30~0.35 내 재튜닝 전제.

> **기각된 1차 안**: "게이트 제거 + 임계값 0.15 유지". 기업회생(0.192~0.300 > 0.15)이 규정으로 오라우팅되어 B를 깨뜨림. 실측으로 폐기.

### 4.2 진짜 이분법 (I4 해소)

law 분기에서 `answerDocs`를 비워 **규정 청크 주입 자체를 제거**. 표시=사용이 자명하게 성립하고 "규정 본문 + 무관 법령 출처" 혼합이 사라진다. (B형 규정 maxScore가 0.03~0.19로 대부분 노이즈이므로 주입 가치 없음. 규정+법령 동시 가치 질의의 규정 보너스는 향후 과제로만 기록.)

### 4.3 인용 검증 파서 교정 (거짓 환각 제거)

`lib/law/verify.ts:46` 정규식 법령명 접미사 `법률|법|령|규칙|규정|조례` 에서 **`규정` 제거**(필요 시 `지침·고시·예규·훈령` 명시 배제). 내부 행정규칙명("○○운용·관리규정")이 법령으로 오인 조회되어 `not_found` → 거짓 `hasHallucination=true`가 되는 것을 차단. 기업회생·개인정보 질의에서 재현된 사용자 직접 피해.

### 4.4 법령 검색 품질 — 레퍼런스(korean-law-mcp) 결정론 레이어 이식

`minScore` 조정만으로는 부족하다(기업회생에서 정답 채무자회생법이 3위 34%, 무관 조세특례제한법 시행령이 1위 77% — **순위 자체가 거꾸로**). 레퍼런스 `chrisryugj/korean-law-mcp`(MIT) 분석으로 근본 원인과 처방을 확정했다. 상세는 §9.

**근본 발산점**: 레퍼런스의 권위 법령검색은 **이름 기반 lawSearch + 결정론적 `scoreLawRelevance` + 필러 제거(`stripNonLawKeywords`) + 별칭 확장**이며, Cohere/임베딩/리랭커는 코드 전체에 **0건**. 법제처 `aiSearch`(의미검색)는 레퍼런스에서 **표시 전용 곁가지**(노이즈 많아 랭킹에 안 씀). 그런데 우리는 정반대로 그 aiSearch를 **유일·주력**으로 삼고 Cohere를 얹었다.

**우리 제약**: B형은 개념형 질의("육아휴직 며칠")라 이름검색이 0건(육아휴직이라는 이름의 법령 없음 → 정답 남녀고용평등법). 개념→법령 매핑엔 aiSearch가 **필수**다. 따라서 통째 이식이 아니라 **aiSearch는 유지하되 레퍼런스의 결정론 레이어를 그 위에 입히는 하이브리드**.

**이식 항목** (`lib/law/search.ts`):
1. **query 정제** — 레퍼런스 `NON_LAW_NAME_RE`/`stripNonLawKeywords` 이식. `searchAiLaw`가 법제처 aiSearch와 Cohere rerank에 보내는 query를 **원문 → 정제 query**로 교체(필러 "내가 진행해야 하는 내용을 알려줘"·"절차/방법/관련" 제거, 개념 토큰 "기업회생/육아휴직"은 보존).
2. **별칭 확장** — 기존 `lib/law/abbreviations.ts` `expandLawAbbreviation`을 정제 단계에 적용(현재 `searchAiLaw` 미적용, `searchLaw`에만 연결됨).
3. **결정론 보정 결합점수** — `rerankAiHits` 직후, Cohere score에 레퍼런스 `scoreLawRelevance` 취지를 가중: **법령'명'에 정제 키워드 포함 시 가점**(채무자회생법名⊇"회생" 가점, 조세특례·독점규제名 무관 감점) + **법률 > 시행령/시행규칙 약한 타이브레이커**(레퍼런스 +5 수준). 최종 정렬 = 결합점수. → 기업회생에서 채무자회생법 1위 역전.
4. **`minScore` 재설정** — 현 0.02는 Cohere raw 기준이라 의미 희박. 결합점수 기준으로 재설정.

**범위 밖(향후 과제)**: 이름검색(`searchByName`/`searchLaw`) 병렬 병합 — 명시 법령명 질의("근로기준법 연차")엔 유효하나, 3시나리오 B형이 전부 개념형이라 현 단계 YAGNI. 질의 분포 데이터 확인 후 재검토.

### 4.7 인용 score 하드코딩 제거 (M11)

`route.ts:298` `citationSources` score `1` 하드코딩 제거 → 실 관련도(결합점수) 표시. 현재 B1/B2/B3 법령이 "관련도 100%"로 과표기되는 문제 해소.

### 4.5 프롬프트 라벨링

`prompts/prompts.md` advisor 섹션 — 내부 규정(○○규정·지침)을 답변에서 `[법령]`으로 라벨링하지 않도록 명문화. (중간보고서 답변에서 규정을 `[법령]`으로 표기한 사례.)

### 4.6 판례 scope creep (M9)

`searchDecisions` 결과에 관련도 컷 또는 호출 조건 강화. 전담기관 케이스에서 "공직선거법위반" 같은 무관 판례가 표면화된 사례 차단.

## 5. 작업 순서 (각 단계 후 8질의 회귀가 acceptance gate)

두 트랙. **트랙1(라우팅 안정화)** 과 **트랙2(법령 검색 품질)** 은 독립적이나 보완적 — 트랙1이 임계값을 올려 B 진입을 늘리므로 트랙2가 더 중요해진다.

**트랙1 — 라우팅 안정화**
1. **4.1 라우팅 교체** — 버그 직격, 필수. `env.ts:39` + `route.ts:211-216`. 게이트 함수 호출 제거.
2. **4.3 인용 파서** — 거짓 환각 경고 직격. `verify.ts:46`(`규정` 접미사 제거).
3. **4.2 이분법 정리** — `route.ts:268` law 분기 `answerDocs=[]`.
4. **4.5 프롬프트** — `prompts.md`(규정을 `[법령]`으로 라벨 금지).
5. **4.6 판례 scope creep** — `searchDecisions` 호출부 관련도 컷.

**트랙2 — 법령 검색 품질 (레퍼런스 이식)**
6. **4.4-(1) query 정제** — `NON_LAW_NAME_RE` 이식 + `searchAiLaw` 입력 정제.
7. **4.4-(2) 별칭 확장** — `expandLawAbbreviation`을 정제 단계 적용.
8. **4.4-(3) 결정론 결합점수** — `rerankAiHits` 후 법령명-키워드 정합 + 법률>시행령 보정.
9. **4.4-(4) minScore 재설정** + **4.7 M11 하드코딩 제거**(`route.ts:298`).

> 트랙2는 인용 검증(4.3)과 연동 — 정확한 법령이 컨텍스트에 와야 인용도 정확해진다.
> **구현 전 1건 실측**: 서버 재기동 후 정제 query로 `searchAiLaw` 후보 50건을 덤프해, 정제가 후보 품질을 실제로 개선하는지 확인(현재 추론). aiSearch가 애초에 정답 후보를 반환 안 하면 결정론 보정도 무력.

## 6. 검증 (회귀 셋)

8질의 고정 셋으로 매 단계 후 라우트·출처·인용을 점검:
- A: 중간보고서 절차 / ict기금 전담기관이란 / **ict 전담기관이란**(버그 질의) → 전부 `regulation`, 규정 출처만
- B: 기업회생 / 육아휴직 / 하도급 / 개인정보 유출 → 전부 `law`, 법령 출처만, `hasHallucination=false`
- C: 오늘 날씨 → 거절, 출처 0

도구: `curl`로 `/api/chat` ndjson 스트림 캡처 → routing/sources/citations 파싱(본 세션 스크립트 재사용).

## 7. 리스크 · 비결정

- **임계값 표본**: 8질의·기업회생 2회 관측 기반. 규정질의가 0.30~0.50 경계에 떨어지면 law 오발 가능. `RELEVANCE_THRESHOLD` env 유지 + `query_log` score 분포로 사후 튜닝.
- **정제 정규식 과잉제거**: `NON_LAW_NAME_RE`에 `절차/방법/기준`이 있어 "행정절차" 같은 개념 일부를 깎을 위험. 보수적 이식 + 8질의 회귀.
- **결정론 보정 가중 튜닝**: 시행령 감점이 과하면 정답이 시행령인 경우(개인정보보호법 시행령) 부당 감점. 레퍼런스처럼 **약한 타이브레이커**로(본법 우선 정도).
- **추론 미검증 1건**: 정제 query가 법제처 aiSearch **후보군** 자체를 개선하는지는 미실측. 구현 전 후보 50건 덤프로 확인(§5 주).
- **이분법 단순화**: 규정+법령 동시 가치 질의의 규정 근거 상실 → 3시나리오 acceptance엔 불필요, 향후 통합 rerank 과제로 기록.
- **DB 스키마 변경 없음** — 전부 애플리케이션 로직/설정.

## 8. 범위 밖 (별도 트랙)

`query_log` 미적재, 에러 원문 누출, 인증 게이트 부재 → 오픈 전 하드닝(`docs/07`) 소관. 본 설계는 RAG 라우팅 정합성만 다룬다.
