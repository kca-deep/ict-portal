# 관리자 페이지: 문(로그인) 먼저 — 6·7장 순서 설계

> **범위**: `edu/session-06.md`의 6장(설정 정합)·7장(관리자 페이지) **구현 순서·분해**만 다룬다.
> 각 장의 *내용*(무엇을 만드는가)은 `edu/session-06.md`가 진실원이며, 이 문서는 그것을 **어떤 순서로, 어떻게 쪼개서** 만들지를 확정한다.
> **날짜**: 2026-07-07 · **전제**: 이 서비스는 로그인 없이 운영(관리자만 비밀번호 보호)

---

## 1. 결정 요약

관리자 페이지(7장)를 **한 덩어리로 만들지 않고 둘로 쪼갠다.**

| 조각 | 별칭 | 성격 | 의존 |
|---|---|---|---|
| **7a** | **문 (로그인/인증 껍데기)** | 데이터 없이도 완결·검증 가능 | 없음 |
| **7b** | **방 (쿼리로그 뷰어)** | 5장이 쌓은 `query_log` 데이터에 의존 | 5장(적재) |

그리고 **문(7a)을 방(7b)보다, 그리고 설정 청소(6장)보다 먼저** 만든다.

### 확정 순서

```
① 5장  로그 적재         (이미 진행 중: query-log.ts·migration·middleware.ts untracked)
② 7a   문(로그인) 만들기  ★ 이번 결정의 핵심
③ 6장  설정 청소          (보안 헤더·vercel.json·부팅 가드 — 이때 /admin 라우트까지 한 번에)
④ 7b   방(로그 표) 채우기
```

`session-06.md` 원안(6장 → 7장 통짜)에서 **7장을 7a/7b로 분해하고 7a를 6장 앞으로 당긴 것**이 유일한 변경이다.

## 2. 왜 문(7a)을 먼저 만드는가

1. **가장 위험한 새 메커니즘을 선검증.** 이번 회차에서 제일 까다로운 건 인증 껍데기다 — 비밀번호 검증 → 서명 httpOnly 쿠키 발급 → 미들웨어의 `/admin/*` 게이트 → service_role 서버 전용 조회. 여기서 삐끗하면 뒤가 다 막히므로, **방을 비워둔 채 문부터 뚫어 검증**한다.
2. **6장이 "진짜 마지막 설정 청소"가 된다.** 6장의 `vercel.json` 정합·보안 헤더는 `/admin`·`/api/admin` 라우트를 반영해야 한다(`session-06.md` 8장 파일맵의 "admin route 반영"). 7a로 라우트가 **먼저 존재**하면 6장에서 한 번에 정리된다. 반대 순서면 7장 이후 `vercel.json`을 재방문해야 한다.
3. **교육 세션 특성상** 초반에 눈에 보이는 산출물(로그인 → 보호된 빈 페이지)이 나와 흐름을 잡기 좋다.

## 3. 7a — 문(로그인/인증 껍데기)

### 3-1. 만드는 것

| 손대는 파일 | 역할 |
|---|---|
| `lib/env.ts` | `ADMIN_PASSWORD` env 추가 |
| `app/api/admin/login/route.ts` (신규) | 비밀번호 검증 → 서명·만료 httpOnly 쿠키 발급 |
| `app/admin/login/` (신규) | 비밀번호 입력 폼(관리자 페이지 안에만, 기존 챗봇 화면과 무관) |
| `middleware.ts` (이미 untracked) | `/admin/*` 진입 시 쿠키 검사 → 없으면 로그인 폼으로 |
| `app/admin/page.tsx` (신규) | **이 단계에선 "로그인 성공" 빈 껍데기만** (표는 7b에서 채움) |

### 3-2. 완료 검증 (데이터 0건이어도 가능)

- 비밀번호 **없이** `/admin` 접근 → **차단**(로그인 폼으로)
- **올바른** 비밀번호 → 빈 관리자 페이지 진입됨
- service_role 키가 **브라우저 네트워크 탭에 노출되지 않음**

### 3-3. 제약 (PoC / YAGNI — 반드시 지킴)

- 인증은 **단일 공유 `ADMIN_PASSWORD` + 서명 httpOnly 쿠키**로 끝낸다.
- **금지**: 회원가입·계정·비밀번호 재설정·역할 분리·소셜 로그인. "문 먼저"가 문을 *크게* 만들라는 뜻이 되면 안 된다.
- 기존 챗봇 화면(`app/page.tsx`·`components/**`)은 건드리지 않는다.

---

## 4. 6장 — 설정 청소 (7a 뒤에)

`session-06.md` 6장 내용 그대로. 단 순서상 **7a 뒤**라서 `/admin`·`/api/admin` 라우트가 이미 존재하므로:

- **보안 헤더**(`next.config.ts`): 전역 적용이 관리자 쿠키·페이지를 깨지 않는지 함께 확인.
- **`vercel.json` 정합**: 없는 라우트 제거 + **실재하는 admin 라우트까지 한 번에** 반영.
- 부팅 가드 복구·env 정합은 원안대로.

→ 6장을 7a 뒤에 두는 덕분에 `vercel.json`을 한 번만 손댄다.

## 5. 7b — 방(쿼리로그 뷰어)

`session-06.md` 7-3·7-4 내용 그대로. 5장이 쌓은 데이터에 의존.

| 손대는 파일 | 역할 |
|---|---|
| `lib/db/query-log.ts` (이미 untracked, 확장) | `listQueryLogs`·`queryLogStats` (service_role 조회·집계) |
| `app/admin/page.tsx` (7a의 빈 껍데기를 채움) | 상단 요약 + 읽기 전용 로그 표 + 행 클릭 상세 |

### 완료 검증

- 5장에서 쌓인 행이 표에 보임
- 요약(질의 수·분기 비율·환각 건수·평균 지연·토큰 합계)이 실제 값으로 뜸
- 행 클릭 → 질문/답변 전문·인용 verdict 상세

- DB 마이그레이션(4a)은 단독 PR 원칙 유지.
