# 관리자 대시보드 — 1년 상한 전체 집계 (5천건 캡 제거)

날짜: 2026-07-20 · 상태: 승인됨 · 대상: `app/admin/page.tsx`, `lib/db/query-log.ts`

## 배경

`queryLogStats` 는 최신 5,000행(`STATS_ROW_CAP`)만 가져와 집계한다. 로그가 5천 건을
넘으면 사용량·이용자 수·비율·토큰 합계가 조용히 과소집계되며 화면에 잘림 표시가
없다. 오픈 후 누적 시 틀린 총계를 정상처럼 보여주는 잠재 결함.

## 결정 (사용자 확정)

- 집계 기간 상한 **1년**. 기간 토글을 `24시간 / 7일 / 30일 / 1년` 으로 개편("전체" 제거).
- 5천 건 초과 시 **JS 페이지네이션**으로 창 내 전 행 집계(RPC 마이그레이션 없음 — PoC 규모).

## 설계

### 1. 기간 토글 (`app/admin/page.tsx`)

- 토글 4개: `24시간(24h) / 7일(7d) / 30일(30d) / 1년(기본)`.
- `period` 미지정 = 1년 — 기존 "전체"(파라미터 없음) 링크가 자연스럽게 1년으로 강등.
- `sinceFromPeriod`: `30d` 분기 추가, 기본 반환값 `now − 365일`.
- `periodLabel` 기본 문구 "최근 1년".

### 2. 커스텀 날짜 1년 클램프

- 유효 `since` = max(`from`, `now − 1년`). `from` 미입력 시 하한 = 1년 전.
- 클램프 발동 시(사용자 `from` 이 1년 이전) 계기판에 안내 문구 표시:
  "1년 이전 데이터는 집계에서 제외됩니다".

### 3. 집계 페이지네이션 (`lib/db/query-log.ts`)

- `queryLogStats` 의 `.limit(STATS_ROW_CAP)` 제거 → `.range(offset, offset+999)`
  1,000행 청크 반복. 반환 행 < 청크 크기면 종료.
- 안전핀: 최대 100청크(100,000행). 도달 시 `QueryLogStats.truncated: true` 반환,
  화면에 잘림 배지 표시(무표시 잘림 금지).
- 집계 본문(KST 환산·공휴일·byRoute·api_usage 합산)은 기존 로직 그대로 재사용.
- `listQueryLogs`(로그 표)는 자체 페이지네이션 보유 — 불변.

### 4. 추이 차트 버킷 (`buildUsageSeries`)

현행 일별 30일 하드컷 제거(1년 조회 시 11개월 소실 방지):

| 조회 창 | 버킷 | 라벨 |
|---|---|---|
| ≤ 2일 | 시간별 | `H시` |
| ≤ 90일 | 일별 | `M/D` |
| 초과 | 주별 | `M/D` (주 시작일) |

1년 ≈ 52포인트.

## 에러·경계

- 청크 fetch 중 Supabase 오류 → 기존과 동일하게 throw(페이지 에러). 부분 집계 미반환.
- 행 0건 → 현행 동작 유지(빈 시리즈 1버킷, 비율 0 가드).
- `truncated` 는 안전핀 도달 시에만 true. UI 배지는 계기판 헤더 옆 소형 텍스트.
