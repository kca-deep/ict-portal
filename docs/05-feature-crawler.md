# ② 공모사업 크롤러 (ICT기금 공모사업 파이프라인)

> **한 줄 요약**: 여러 정부·공공기관 홈페이지에 흩어진 **공모/지원사업 공고**를 자동으로 모아, AI가 ICT기금 비R&D 공고만 골라내고 검색하기 쉽게 정리해 주는 기능입니다.
>
> **상태: 8월 말 완성 예정 (아직 미착수 미래 기능)** — 아래 내용은 설계안이며 현재 구현된 것은 없습니다.

> 참고 용어
> - **크롤러(crawler)**: 웹사이트를 자동으로 방문해 내용을 수집하는 프로그램.
> - **공모/지원사업 aggregator(애그리게이터)**: 여러 곳에 흩어진 지원사업 공고를 한곳에 모아 주는 도구. (※ 채용 공고가 아니라 정부·기관의 지원사업 공고를 다룹니다.)
> - **임베딩(embedding)**: 글의 의미를 숫자 배열로 바꾼 값. 의미가 비슷한 글끼리 가깝게 표현됩니다.

---

## 1. 목표

- 전담기관·주요 유관기관(과기정통부, NIPA, IITP 등) 홈페이지의 **공모사업 공고를 주기적으로 자동 수집**합니다.
- **AI가 ICT기금 비R&D 공고만 판별**해서 추려 냅니다.
- 공고 내용을 **자동 요약 + 카테고리 분류**해, 사용자가 검색하고 열람하기 쉬운 형태로 제공합니다.

## 2. 입력과 출력

| 구분 | 내용 |
|---|---|
| 입력 | 미리 등록해 둔 크롤링 대상 목록 (`crawler_sources` 테이블) |
| 출력 | 정리된 공고를 `announcements` 테이블에 저장 + 관리자 페이지에서 열람 |

## 3. 처리 흐름 (단계별)

전체 흐름은 **6시간마다 자동으로** 한 번씩 돌아갑니다. Vercel Cron(예약 실행 기능)이 정해진 시각에 수집 작업을 시작합니다.

| 단계 | 하는 일 | 비고 |
|---|---|---|
| 1 | 수집 대상 불러오기 | `crawler_sources`에서 `enabled=true`인 사이트만 |
| 2 | 사이트 HTML 가져오기 | `fetch` + **cheerio**로 정적 HTML 다운로드 (타임아웃 10초, 실패 시 부분 실패로 기록) |
| 3 | 공고 목록 추출 | 목록 페이지에서 공고 ID·제목·게시일·상세 URL을 뽑음. 이미 받은 공고는 건너뛰고 **신규 공고만** 처리 |
| 4 | 상세 본문 추출 | 상세 페이지를 가져와 본문 텍스트만 정리해 저장 |
| 5 | AI 분류 | **Claude `claude-sonnet-4-6`**로 ICT기금 비R&D 여부와 카테고리 판별 |
| 6 | 핵심 정보 구조화 | 지원대상·지원방식·사업분야·금액·접수기간을 JSON으로 정리 |
| 7 | 임베딩 생성·색인 | **OpenAI `text-embedding-3-small`(1024차원)**로 본문 임베딩을 만들어 검색용으로 저장 |
| 8 | 저장 (중복 방지) | `announcements`에 INSERT/UPSERT. 같은 공고가 다시 들어오면 새로 쌓지 않고 갱신 |
| 9 | 실행 결과 기록 | 종료 시각·상태·처리 건수를 `crawl_runs`에 기록 |

> **임베딩 표기 정리**: 공고 본문 임베딩은 **OpenAI `text-embedding-3-small`(1024차원)** 을 사용합니다. 검색 결과의 정확도를 더 높이고 싶을 때는 별도 단계로 Cohere `rerank-v4.0`(재정렬)을 덧붙일 수 있습니다. (※ 재정렬은 임베딩과 다른 별개 단계입니다.)

## 5. 기술 선택

### 5.1 HTML 수집 방법

- **1순위**: 표준 `fetch` + **cheerio** — 화면이 고정된(정적) HTML 사이트에 사용합니다.
- **2순위 검토**: 화면을 JavaScript로 그리는 사이트는 위 방법으로 안 됩니다. 이때는 다음을 검토합니다.
  - 외부 스크래핑 서비스(ScrapingBee, Bright Data 등) — 권장.
  - Vercel 함수 밖에 별도 수집 워커(Railway 등) — 최후의 수단.

### 5.2 분류 모델

- **공고 분류 LLM**: **Claude `claude-sonnet-4-6`** 한 가지로 통일합니다. ICT기금 비R&D 공고인지(여부)와 어떤 카테고리인지를 판별합니다.
- 어드바이저 기능과 같은 모델을 써서 키·설정을 한곳에서 관리합니다.

### 5.3 분류 프롬프트 (초안)

```
다음은 정부·공공기관 공고입니다.

[공고 제목]
{title}

[공고 본문]
{content}

다음을 판별하세요:
1. is_ict_fund: ICT기금 비R&D 공모사업인가? (true/false)
2. category: 다음 중 가장 적합한 카테고리 (해당 없으면 "기타")
   - "비R&D-스타트업지원"
   - "비R&D-인력양성"
   - "비R&D-인프라"
   - "비R&D-국제협력"
   - "R&D" (해당 시 is_ict_fund=false)
   - "타분야"
   - "기타"
3. extracted: 핵심 정보 JSON
   {
     "target": "지원대상 (예: 중소·벤처기업)",
     "support_type": "지원방식 (자금/멘토링/공간 등)",
     "fund_amount": "지원금액 (텍스트)",
     "application_period": "접수기간",
     "agency": "주관기관"
   }

JSON 으로만 응답하세요.
```

→ 구조화 출력(`tool_use` 등)으로 정해진 형식의 JSON만 받도록 강제합니다.

## 6. Vercel Cron 설정 (예약 실행)

```jsonc
// vercel.json
{
  "crons": [
    { "path": "/api/cron/crawl-announcements", "schedule": "0 */6 * * *" }
  ]
}
```

- `0 */6 * * *` 은 **6시간마다 한 번** 실행한다는 뜻입니다.
- 한 번 실행에 너무 오래 걸리지 않도록, 사이트 수 × 평균 신규 공고 수 × 분류 시간을 미리 측정합니다.
- 처리량이 많으면 **사이트별로 나눠서** 시간대마다 다른 사이트를 처리하도록 분할합니다.

## 7. 사용자 화면

### 관리자 화면 — 챗봇 admin에 통합

크롤러의 관리 기능은 **별도 도구로 두지 않고 챗봇 관리자(admin) 화면에 통합**합니다. 챗봇이 공모 공고를 답변의 정보원으로 쓰는 만큼, 그 데이터의 수집·품질을 챗봇 운영 화면과 같은 곳에서 관리하는 것이 자연스럽습니다. (통합 설계 상세: [`04-feature-advisor.md` §9 관리자 화면](./04-feature-advisor.md))

챗봇 admin 안의 공모 크롤러 탭에서 다루는 것:

- 신규 공고 목록 (게시일·마감일 기준 정렬), 접수 중 / 마감 임박 / 마감 현황
- 필터: 기관, 카테고리, 마감 임박, ICT기금 여부
- 검색: **키워드 + 시맨틱(OpenAI 임베딩) 하이브리드** — 단어가 똑같이 들어간 글뿐 아니라 의미가 비슷한 글도 함께 찾아 줍니다.
- 수집 소스 관리(`crawler_sources` 등록·수정·on/off), 실행 이력·실패 알림(`crawl_runs`), AI 분류 결과 검수, 수동 재실행.

> 운영자는 "챗봇이 무엇을 답하는가(채팅 로그)"와 "그 근거 공고가 어떻게 들어오는가(크롤러)"를 한 화면에서 함께 봅니다.

### 일반 사용자용 (옵션)

- ICT기금 비R&D 공고만 추린 공개 페이지
- RSS·Webhook으로 외부 시스템 연동 검토

## 8. 보안·운영 수칙

- **robots.txt 준수** — 수집 전 사이트의 수집 허용 규칙을 확인하고, 거부하는 사이트는 제외합니다.
- **요청 속도 제한** — 사이트당 동시 요청 1개, 요청 사이 최소 1초 간격을 둡니다.
- **신원 명시** — 요청에 `PIMS-Crawler/1.0 (+연락처)` 식별 정보를 붙여 누가 수집하는지 알 수 있게 합니다.
- **저작권 배려** — 원문 전체 저장은 내부 분석용으로만 쓰고, 사용자에게는 제목·요약·원본 링크 위주로 보여 줍니다.
- **장애 격리** — 한 사이트가 실패해도 나머지는 계속 진행하고, 실행 상태를 `partial`(부분 성공)로 기록합니다.

## 9. 평가 지표

| 지표 | 목표 |
|---|---|
| 일일 신규 공고 수집률 (수동 확인 대비) | ≥ 95% |
| ICT기금 비R&D 분류 정확도 | ≥ 0.90 |
| 평균 크롤링 1회 소요 시간 | ≤ 5분 |
| 마감 7일 전 공고 누락 사고 | 0건 |
