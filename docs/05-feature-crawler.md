# ② 공모사업 크롤러 (ICT기금 공모사업 파이프라인)

> **한 줄 요약**: 여러 정부·공공기관의 **공모/지원사업 공고**를 자동으로 모아, AI가 ICT기금 비R&D 공고만 골라내고 검색하기 쉽게 정리해 주는 기능입니다. 공식 **구조화 API(알리오 플러스)를 1순위**로 쓰고, API가 없는 곳만 **웹 스크래핑(티어 전략)**으로 보완합니다.
>
> **상태: 8월 말 완성 예정 (아직 미착수 미래 기능)** — 아래 내용은 설계안이며 현재 구현된 것은 없습니다.
>
> **개정 이력**: 2026-06-23 — 데이터 소스를 **구조화 API 우선**으로 재정렬(알리오 플러스 API), HTML 수집에 **추출 티어 전략(티어0~3, LLM 자가추론 캐싱 포함)** 도입, **Jina Reader** 기반 첨부/PDF 수집과 **한국 IP·WAF 제약**을 명문화.

> 참고 용어
> - **크롤러(crawler)**: 웹사이트를 자동으로 방문해 내용을 수집하는 프로그램.
> - **공모/지원사업 aggregator(애그리게이터)**: 여러 곳에 흩어진 지원사업 공고를 한곳에 모아 주는 도구. (※ 채용 공고가 아니라 정부·기관의 지원사업 공고를 다룹니다.)
> - **구조화 API**: 사람이 보는 HTML 대신, 프로그램이 바로 쓰도록 정리된 데이터(JSON)를 돌려주는 공식 창구. 스크래핑보다 안정적이고 깨질 일이 적습니다.
> - **셀렉터(selector)**: HTML에서 "제목은 여기, 날짜는 저기"를 가리키는 규칙(CSS 경로).
> - **임베딩(embedding)**: 글의 의미를 숫자 배열로 바꾼 값. 의미가 비슷한 글끼리 가깝게 표현됩니다.

---

## 1. 목표

- 전담기관·주요 유관기관(과기정통부, NIPA, IITP 등)의 **공모사업 공고를 주기적으로 자동 수집**합니다.
- 가능한 곳은 **공식 구조화 API(알리오 플러스)로 안정적으로** 받고, API가 없는 곳만 **웹 스크래핑으로 보완**합니다.
- **AI가 ICT기금 비R&D 공고만 판별**해서 추려 냅니다.
- 공고 내용을 **자동 요약 + 카테고리 분류**해, 사용자가 검색·열람하기 쉬운 형태로 제공합니다.

## 2. 입력과 출력

| 구분 | 내용 |
|---|---|
| 입력 | 미리 등록해 둔 수집 대상 목록 (`crawler_sources` 테이블) — 소스마다 **API형 / HTML형**을 구분 |
| 출력 | 정리된 공고를 `announcements` 테이블에 저장 + 관리자 페이지에서 열람 |

## 3. 데이터 소스 전략 (구조화 API 우선)

스크래핑은 화면 구조가 바뀌면 깨지고, 사이트마다 손이 갑니다. 그래서 **공식 구조화 소스를 먼저** 쓰고, 없을 때만 스크래핑합니다. (어드바이저 ①이 법령을 자체 크롤링하지 않고 **법제처 OpenAPI 직접 호출**을 쓰는 것과 같은 철학입니다.)

| 우선순위 | 소스 | 설명 |
|---|---|---|
| **1순위** | **알리오 플러스 API** (`/api/business` 사업 정보) | 기획재정부 공식 공공기관 정보 연동 API. 사업명·기간·지원대상·신청방법·원문 URL을 **JSON으로** 반환. 스크래핑 없이 다수 기관의 공모/지원사업을 표준 형식으로 확보 |
| 2순위 | 대상별 공식 API / RSS / sitemap | 기관이 자체 제공하는 구조화 창구가 있으면 그것을 사용 |
| 3순위 | **HTML 스크래핑** (§5 티어 전략) | 위가 없는 기관만. 정적 HTML은 cheerio, 그 외는 Jina Reader/호스티드 |

### 3.1 알리오 플러스 API 요점

- **호스트/프로토콜**: `openapi.alioplus.go.kr`, 모든 호출 **HTTP POST**, **HTTPS 미지원**.
- **인증**: 도메인별 **인증키 4종**(기관/사업/시설/행사), 헤더 `X-API-AUTH-KEY`. 키의 `+` 문자는 `%2B`로 URL 인코딩.
- **공모사업에 쓰는 엔드포인트**: `/api/business`(사업 정보). 주요 필드 `apbaNa`(기관), `bsnNa`(사업명), `bsnDsc`(설명), `bsnStDt`/`bsnEndDt`(기간), `guideTar`(대상), `guideMth`(신청방법), `siteUrl`(원문).
- **필터(카테고리 코드)**: `schSvcCate=05`(사업지원), 사업유형 `schFstCateCd` = `B07`(산업진흥)·`B03`(교육연구)·`B09`(취업·직업) 등. → 코드 필터만으로 ICT기금 성격 공고를 1차 좁힘.
- **응답 형식**: JSON. **페이징**: `pageSize`로 건수 제어(명시적 offset 파라미터 없음 → 전량 수신 후 날짜 필터 권장).

> **한계와 보완**: 알리오 플러스는 **알리오에 게시하는 기관**만 커버합니다. 비게시 기관·첨부 상세·실시간 신규는 누락될 수 있으므로, 그런 기관은 §5의 HTML 스크래핑으로 보완합니다(하이브리드).

## 4. 처리 흐름 (단계별)

전체 흐름은 **6시간마다 자동으로** 한 번씩 돌아갑니다. Vercel Cron(예약 실행)이 정해진 시각에 수집 작업을 시작합니다. 소스의 종류(`source_type`)에 따라 **수집 단계만 갈라지고**, 그 뒤(정규화→분류→저장)는 **공통 파이프라인**을 함께 씁니다.

| 단계 | 하는 일 | 비고 |
|---|---|---|
| 1 | 수집 대상 불러오기 | `crawler_sources`에서 `enabled=true`만. `source_type`으로 분기 |
| 2a | **(API형)** 알리오/공식 API 호출 | `source_type='alio_api'`/`'api'`. `config`의 카테고리 코드 필터로 조회 → JSON 수신 |
| 2b | **(HTML형)** 페이지 수집 | `source_type='html'`. §5 **추출 티어 전략**(cheerio / Jina Reader / 호스티드)으로 본문·첨부 URL 추출. 타임아웃 10초, 실패 시 부분 실패로 기록 |
| 3 | 신규 항목 추리기 | `external_id`로 **이미 받은 공고는 건너뜀**. 아래 LLM 호출 전에 dedup하여 비용 절약 |
| 4 | 본문·첨부 정리 | 본문 텍스트 + 첨부 다운로드 URL. PDF 첨부는 본문 추출, HWP는 전용 파서(§5.4) |
| 5 | AI 분류 | **Claude `claude-sonnet-4-6`**로 ICT기금 비R&D 여부·카테고리 판별 (+신뢰도·근거) |
| 6 | 핵심 정보 구조화 | 지원대상·지원방식·사업분야·금액·접수기간을 JSON으로 정리 |
| 7 | 임베딩 생성·색인 | **OpenAI `text-embedding-3-small`(1024차원)**. **본문 해시가 바뀐 경우에만** 재임베딩 |
| 8 | 저장 (중복 방지) | `announcements`에 UPSERT. `unique(source_id, external_id)` 충돌 시 마감일 등 갱신 |
| 9 | 실행 결과 기록 | 종료 시각·상태·처리 건수를 `crawl_runs`에 기록. 한 소스 실패가 배치 전체를 멈추지 않음 |

> **임베딩 표기 정리**: 공고 본문 임베딩은 **OpenAI `text-embedding-3-small`(1024차원)** 입니다. 검색 정확도를 더 높이려면 별도 단계로 Cohere `rerank-v3.5`(재정렬)을 덧붙일 수 있습니다.

## 5. 기술 선택

### 5.1 수집 도구 (대상 유형별)

| 대상 | 도구 | 비고 |
|---|---|---|
| 공식 API/RSS 있음 | API 직접 호출 | **항상 우선**(§3) |
| 정적 HTML | `fetch` + **cheerio** | 무료·결정적. 구조를 아는 사이트에 최적 |
| 본문+첨부+PDF 한 번에 | **Jina Reader**(`r.jina.ai/<url>`) | 페이지를 마크다운으로 변환. `X-With-Links-Summary`로 **첨부 다운로드 URL 일괄 수집**, **PDF 첨부 내용까지 추출**. 무료 한도(키 없이 ~20 RPM, 무료키 1천만 토큰) |
| JS 렌더링 / anti-bot | 호스티드(Firecrawl 등) **REST** | 필요할 때만. Vercel 함수에 헤드리스 Chromium 직접 탑재는 **비권장**(번들·콜드스타트) |

> **MCP/스킬은 프로덕션 경로에 두지 않습니다.** Firecrawl·Playwright·Bright Data·`insane-search`(스킬)·`kordoc`(MCP) 등은 **개발·검증·일회성 적재용**입니다. 운영 크롤러는 위 **순수 라이브러리 + REST API**로만 구성합니다. (korean-law를 `lib/law/` 자체 함수로 구현한 것과 같은 이유.)

### 5.2 한국 IP·WAF 제약 (실측 필요)

- 일부 `.go.kr` 사이트는 WAF(WAPPLES/AIWAF)로 **비(非)한국 IP를 차단**할 수 있습니다. Vercel은 미국 리전이고, `icn1`(서울)로 고정해도 **데이터센터 IP라 통과를 보장하지 못합니다.**
- 따라서 **Phase 0 스파이크에서 사이트별로 "오픈 / WAF 차단"을 실측 분류**합니다(§7).
  - **오픈**: cheerio·Jina로 그대로 수집. (예: 테스트한 `kca.kr`은 Jina로 본문+첨부+PDF까지 정상 수집됨.)
  - **차단**: 한국 거주 IP 언락커(Bright Data `country=kr`) 또는 **한국 VPS 릴레이**를 경유. PoC에서는 **꼭 필요한 사이트에 한해** 도입.
- 일반 웹(비 `.go.kr`) 대상이라면 이 제약은 대체로 사라지고, **Jina/Firecrawl 무료~저가 티어로 충분**합니다.

### 5.3 추출 티어 전략 (셀렉터 유지보수 자동화) — 핵심

사이트마다 화면 구조가 달라 셀렉터가 제각각이지만, **사람이 일일이 짜지 않도록** 4단계로 운영합니다. 가능한 한 낮은 티어로 시작하고, **티어3(LLM 자가추론 캐싱)을 확장 장치**로 둡니다.

| 티어 | 방식 | 유지보수 | 언제 |
|---|---|---|---|
| **0. 셀렉터 없음** | Jina/cheerio 기본 마크다운 그대로 | **0** | **기본값.** 메뉴 노이즈가 섞여도 다운스트림 분류·임베딩이 보일러플레이트를 무시 → 정확도엔 무해(토큰만 약간↑) |
| **1. 공용 셀렉터** | `X-Remove-Selector`에 공통 보일러플레이트(header·footer·.gnb·#lnb) **1벌** | 낮음(사이트별 아님) | **eGovFrame 계열은 템플릿이 거의 동일** → 한 벌이 여러 사이트 커버. 토큰 절약 |
| **2. 사이트별 셀렉터** | `config.selectors`에 개별 저장 | 높음 | **노이즈 심한 고가치 사이트만** 선별적으로 |
| **3. LLM 추론+캐싱 (자가치유)** | 신규·개편 시 **Claude 1회 호출**로 셀렉터를 추론 → `config`에 캐시. 추출 수율이 임계 이하로 떨어지면 **자동 재추론** | **자동** | 사이트 수가 늘 때의 **표준 확장 메커니즘**. 사람이 셀렉터를 짜지 않음 |

**티어3 동작 규칙(채택안)**

1. **추론 트리거**: ① 신규 소스 등록 시, ② 셀렉터 추출 **수율 저하 감지 시**(예: 최근 실행에서 본문/목록이 비거나 `min_yield` 미만), ③ 운영자 수동 재추론.
2. **추론 호출**: 대상 페이지 HTML(또는 Jina 마크다운) 일부를 Claude에 주고 **`config.selectors` 스키마(list/title/date/url/body/attachments)에 맞는 셀렉터 JSON**을 구조화 출력으로 받습니다.
3. **캐싱**: 결과를 `crawler_sources.config.selectors`에 저장하고 `config.infer.last_inferred_at`·`tier`를 기록. 이후 실행은 **캐시된 셀렉터로 무(無)LLM 추출** → 비용은 1회성으로 상각.
4. **검증·롤백**: 추론 직후 1건을 시범 추출해 필수 필드(title·url) 충족을 확인. 실패하면 **티어0(셀렉터 없음)로 폴백**해 수집은 지속하고 재추론 큐에 적재.
5. **family 공유**: 같은 템플릿(`template_family`, 예: `egovframe-board`)으로 묶인 소스는 **셀렉터를 공유**해 추론 횟수를 줄입니다.

> 요지: "다중 사이트 = 각각 다르게"는 맞지만, 이를 **(공용 셀렉터 + LLM 자가추론 캐싱)으로 자동화**해 사람 손을 0에 수렴시킵니다.

### 5.4 첨부파일 처리

- **다운로드 URL 수집**: Jina `X-With-Links-Summary`, 또는 사이트 패턴 정규식(예: `kca.kr`의 `fileDownload.do?...&fileSn=N`).
- **PDF**: 다운로드 URL을 다시 Jina에 넣어 **본문 텍스트 추출**(텍스트 레이어 PDF는 양호, 스캔본은 OCR 품질 한계).
- **HWP/HWPX**: Jina 불가. **전용 파서 라이브러리**로 추출(개발 단계에서 `kordoc` MCP로 품질 검증 후, 프로덕션은 동등 라이브러리). PDF가 함께 첨부된 공고는 **PDF를 우선** 사용.

### 5.5 분류 모델

- **공고 분류 LLM**: **Claude `claude-sonnet-4-6`** 한 가지로 통일. 어드바이저와 같은 모델·키·설정을 공유합니다.
- API형 소스는 카테고리 코드(§3.1)로 **규칙 기반 1차 분류**를 하고, **모호할 때만 Claude를 호출**해 토큰을 아낍니다.

### 5.6 분류 프롬프트 (초안)

```
다음은 정부·공공기관 공고입니다.

[공고 제목]
{title}

[공고 본문]
{content}

다음을 판별하세요:
1. is_ict_fund: ICT기금 비R&D 공모사업인가? (true/false)
2. category: 다음 중 가장 적합한 카테고리 (해당 없으면 "기타")
   - "비R&D-스타트업지원"
   - "비R&D-인력양성"
   - "비R&D-인프라"
   - "비R&D-국제협력"
   - "R&D" (해당 시 is_ict_fund=false)
   - "타분야"
   - "기타"
3. confidence: 위 판별의 확신도 (0.0~1.0)
4. reasoning: 판단 근거 (한두 문장, 감사·검수용)
5. extracted: 핵심 정보 JSON
   {
     "target": "지원대상 (예: 중소·벤처기업)",
     "support_type": "지원방식 (자금/멘토링/공간 등)",
     "fund_amount": "지원금액 (텍스트)",
     "application_period": "접수기간",
     "agency": "주관기관"
   }

JSON 으로만 응답하세요.
```

→ 구조화 출력(`tool_use` 등)으로 정해진 형식의 JSON만 받도록 강제합니다.
→ **`confidence`가 임계(예: 0.7) 미만이면 자동 게시하지 않고 관리자 검수 큐로** 보냅니다(§8 화면).

### 5.7 `crawler_sources.config` 규약 (계획)

소스별 수집 설정은 코드가 아니라 **DB(`config` jsonb)** 에 두어, 사이트 추가·수정이 **배포 없이 데이터 변경**으로 끝나게 합니다. (실제 컬럼 정의·인덱스·RLS는 **데이터 모델 문서/마이그레이션에서 단독 PR로** 확정 — `03-data-model.md`.)

```jsonc
// source_type: 'alio_api' | 'api' | 'html'
// config 예시 (HTML형, 티어3 적용)
{
  "fetcher": "jina",                 // 'fetch' | 'jina' | 'hosted'
  "template_family": "egovframe-board",
  "extract_tier": 3,                 // 0 | 1 | 2 | 3
  "selectors": {                     // 티어2~3에서 채움(티어3은 LLM이 자동 생성)
    "list": "...", "title": "...", "date": "...",
    "url": "...", "body": "...", "attachments": "..."
  },
  "infer": {                         // 티어3 자가추론 메타
    "enabled": true,
    "last_inferred_at": "2026-08-xx",
    "min_yield": 0.8
  },
  "attachment": { "types": ["pdf", "hwp"], "pdf_parser": "jina", "hwp_parser": "lib" }
}

// config 예시 (알리오 API형)
{
  "endpoint": "/api/business",
  "filters": { "schSvcCate": "05", "schFstCateCd": ["B07", "B03", "B09"], "pageSize": 1000 }
}
```

## 8. Vercel Cron 설정 (예약 실행)

```jsonc
// vercel.json
{
  "crons": [
    { "path": "/api/cron/crawl-announcements", "schedule": "0 */6 * * *" }
  ]
}
```

- `0 */6 * * *` 은 **6시간마다 한 번** 실행한다는 뜻입니다.
- 한 번 실행이 너무 길어지지 않도록 사이트 수 × 평균 신규 공고 수 × 분류 시간을 미리 측정합니다.
- 처리량이 많으면 **사이트별로 나눠서** 시간대마다 다른 사이트를 처리하도록 분할합니다.

## 9. 사용자 화면

### 관리자 화면 — 챗봇 admin에 통합

크롤러 관리 기능은 **별도 도구로 두지 않고 챗봇 관리자(admin) 화면에 통합**합니다. 챗봇이 공모 공고를 답변의 정보원으로 쓰는 만큼, 데이터 수집·품질을 챗봇 운영 화면과 같은 곳에서 관리하는 것이 자연스럽습니다. (통합 설계 상세: [`04-feature-advisor.md` §9 관리자 화면](./04-feature-advisor.md))

챗봇 admin 안의 공모 크롤러 탭에서 다루는 것:

- 신규 공고 목록 (게시일·마감일 기준 정렬), 접수 중 / 마감 임박 / 마감 현황
- 필터: 기관, 카테고리, 마감 임박, ICT기금 여부
- 검색: **키워드 + 시맨틱(OpenAI 임베딩) 하이브리드** — 단어가 같은 글뿐 아니라 의미가 비슷한 글도 함께 찾습니다.
- 수집 소스 관리(`crawler_sources` 등록·수정·on/off, `source_type`·`config` 편집), 실행 이력·실패 알림(`crawl_runs`)
- **저신뢰 분류 검수 큐**(`confidence` 임계 미만) — 운영자가 확인·정정하면 게시. 정정 결과는 분류 개선 자료로 누적
- **티어3 재추론 트리거** 수동 실행 + AI 분류 결과 검수

> 운영자는 "챗봇이 무엇을 답하는가(채팅 로그)"와 "그 근거 공고가 어떻게 들어오는가(크롤러)"를 한 화면에서 함께 봅니다.

### 일반 사용자용 (옵션)

- ICT기금 비R&D 공고만 추린 공개 페이지
- RSS·Webhook으로 외부 시스템 연동 검토

## 10. 보안·운영 수칙

- **robots.txt 준수** — 수집 전 사이트의 수집 허용 규칙을 확인하고, 거부하는 사이트는 제외합니다.
- **요청 속도 제한** — 사이트당 동시 요청 1개, 요청 사이 최소 1초 간격.
- **신원 명시** — 요청에 `PIMS-Crawler/1.0 (+연락처)` 식별 정보를 붙입니다.
- **저작권 배려** — 원문 전체 저장은 내부 분석용으로만, 사용자에게는 제목·요약·원본 링크 위주로 노출. 유료·독점 문서는 본문 대신 링크로 대체.
- **개인정보** — 공고 외 개인정보는 수집·저장하지 않습니다.
- **외부 키 관리** — 알리오 인증키 4종·(도입 시)언락커 키는 환경변수로만 관리하고 커밋 금지(`07-security-ops.md`).
- **장애 격리** — 한 사이트가 실패해도 나머지는 계속 진행하고, 실행 상태를 `partial`(부분 성공)로 기록합니다.
