# PIMS — ICT기금 사용자 중심 AX서비스 기획 개요

> **한 줄 요약**: 불특정 공개 이용자가 로그인 없이 쓰는 챗봇 서비스. 기금 규정과 법령에 대한 질문에 AI가 근거를 들어 답하고(①), 공모사업 공고를 모아 보여주며(②), 봇·악용 방지(Turnstile·레이트리밋)와 운영을 위한 배포·보안 기반까지 함께 갖춘다.

> 본 문서는 진행 상황에 맞춰 갱신하는 살아있는 문서다. (최근 현행화: 2026-06-09)

---

## 1. 프로젝트 정체성

| 항목 | 내용 |
|---|---|
| 공식 명칭 | ICT기금 사용자 중심 AX서비스 구축 계획(안) |
| 시스템 별칭 | (가칭) **PIMS** — ICT기금 사업정보관리시스템 |

| 원본 기획서 | `붙임3. 사업계획서(ICT기금 사용자 서비스 구축).hwpx` |

- **AX**(AI Transformation, AI 전환): 업무에 AI를 적용해 일하는 방식을 바꾸는 것.
- 이 서비스의 중심은 **① 규정·법령 어드바이저**(AI 챗봇)다. 나머지 기능은 이를 보조한다.

---

## 2. 추진 배경

- 기금 규정과 관련 법령을 일관되게 해석해 주는 도구가 없다. 복잡한 질문일수록 담당자마다 답이 달라진다.
- 같은 사업 아이템이 여러 곳에서 **중복 지원**받는 것을 사전에 거를 정보가 흩어져 있다.
- 외부 기관 담당자가 여러 기관 공고를 직접 찾아다녀야 해서 비효율적이다.

---

## 3. 이용 대상과 접근 정책

- **이용 대상**: **불특정 공개 이용자**. 로그인 없이 접속 가능.
- **봇·악용 방지**: Turnstile 봇 게이트(토글/키 기반, 기본 OFF)와 IP 레이트리밋·일일 호출 캡(기본 OFF)으로 통제. 키·토글 부재 시 게이트 없음(기존 동작 유지).
- **색인 API 보호**: `/api/ingest`는 `INGEST_SECRET` 헤더 인증 필수. 외부 사용자 차단.
- **채팅 로그 적재**: 모든 질의·응답을 로그(`query_log` 테이블)에 남긴다. 관리자는 관리자 화면에서 전체 통계(집계)와 개별 대화의 세부 내용을 본다.

## 4. 3대 기능 + 운영 기반

### 3대 기능

| # | 기능 | 핵심 내용 | 상세 문서 |
|---|---|---|---|
| ① | **규정·법령 어드바이저** | 내부 규정·법령 근거로 답하는 AI 챗봇. 근거 인용을 검증해 틀린 답(환각)을 줄인다. | [04-feature-advisor.md](./04-feature-advisor.md) |
| ② | **공모사업 크롤러** | 유관기관 공고를 자동 수집하고 AI로 분류해 모아 보여준다. | [05-feature-crawler.md](./05-feature-crawler.md) |
| ③ | **중복수혜 조회** (선택) | 신청 과제와 기존 과제가 겹치는지 유사도로 비교한다. 별도 상세 문서 없이 개념만 둔다. | (별도 문서 없음) |

> **환각**(hallucination): AI가 근거 없이 그럴듯하게 지어내는 잘못된 답.
> ③은 8월 이후 여건에 따라 도입하는 선택 항목이다.

### 운영 기반 (오픈·운영을 위한 토대)

3대 기능과 별개로, 서비스를 실제로 열고 안정적으로 운영하기 위한 기반을 함께 만든다.

| 항목 | 내용 |
|---|---|
| 배포 | Vercel에 올려 외부에서 접속 가능한 환경을 구성한다. |
| 보안 하드닝 | 오픈 전 환경설정 점검과 취약점 보완(하드닝)을 거친다. |
| 관리자 채팅 로그 | 위 3에서 설명한 질의·응답 로그를 관리자 화면에서 통계·개별 조회한다. |

> **하드닝**(hardening): 알려진 약점을 미리 막아 시스템을 단단하게 만드는 작업.

## 5. ① 어드바이저가 답을 만드는 방식 (요약)

이 서비스의 핵심이라 흐름만 미리 짚는다. 자세한 내용은 [04-feature-advisor.md](./04-feature-advisor.md) 참고.

| 단계 | 사용 기술 | 설명 |
|---|---|---|
| 1. 문서 색인 | OpenAI **`text-embedding-3-small`** (1024차원) | 규정·매뉴얼 문서를 숫자 벡터로 바꿔 미리 저장한다. |
| 2. 질의 변환 | 위와 **같은** 임베딩 모델·차원 | 사용자 질문도 같은 방식으로 벡터화해 비슷한 문서를 찾는다. |
| 3. 재정렬 | Cohere **`rerank-v3.5`** | 찾은 문서들을 질문과 얼마나 관련 있는지 다시 점수 매겨 정렬한다. |
| 4. 분기 판단 | 위 재정렬 관련도 점수 | 점수가 기준치 이상이면 **내부 규정만**으로 답한다. 미만이면 **법령**을 조회해 답한다. (둘을 합치지 않고 하나로 분기) |
| 5. 법령 조회 | **법제처 OpenAPI 직접 호출** (자체 구현 도구 `lib/law/`) | 분기에서 법령이 필요할 때 법제처 자료를 불러온다. |
| 6. 답변 생성 | Anthropic **`claude-sonnet-4-6`** | 근거를 바탕으로 답을 만든다. 스트리밍 출력 + 프롬프트 캐싱 적용. |

- **임베딩**(embedding): 글의 의미를 숫자 벡터로 바꿔 비슷한 글끼리 가까이 놓는 기술. 색인과 질의가 **같은 모델·차원**이어야 비교가 된다. 이 모델은 교체·재색인 없이 영구 유지한다.
- **재정렬/Rerank**: 검색 결과를 질문과의 관련도 순으로 다시 매기는 별도 단계. 임베딩과는 무관한 후처리다.
- **법령 조회 방식**: 법제처 국가법령정보 공동활용 OpenAPI(`lawSearch.do`/`lawService.do`)를 **직접 호출하는 자체 구현 도구**(`lib/law/`)를 쓴다. 개발 환경의 korean-law MCP는 Vercel 서버리스 함수에 상주할 수 없어, 동일 기능을 자체 함수로 구현했다(법제처 공식 데이터·인용 검증·`law_cache` 캐싱은 그대로 유지).
- 검색 대상 테이블: `documents`(매뉴얼), `regulation`(ICT기금 규정).
